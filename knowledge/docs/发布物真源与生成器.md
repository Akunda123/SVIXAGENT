**改文案的正确顺序**（改完必须重生成，否则守卫会报不一致）：

> ⚠️ 真源 `README-发布版草案-v2.md` 与产物 `docs/demo/*.html` 都在 `.gitignore` 里（**开发侧文件**，不进公开仓库）：
> 也就是说 `README.md` 是**发布物**、草案是它的**开发侧真源**。在干净 clone 里没有草案，只能手写 README（或先补草案）。

```
改 README-发布版草案-v2.md
  → node tools/gen-github-readme.cjs      # README.md
  → node tools/gen-demo-data.cjs          # electron/src/help/index.html + docs/demo/index.html
  → node tools/gen-demo-rec.cjs           # docs/demo/rec.html
  → node tools/check-demo-page.cjs        # 独立解析真源再比对，必须 exit=0
```

## 数量声明的连锁反应

工具数会出现在**草案正文**里，并被上面三个生成器带进 README / 帮助页 / 演示页。改工具数时：

1. `node tools/check-tool-inventory.cjs` 会逐处报「N 个 MCP 工具 / MCP 工具面（N 个）/ N 个工具」的漂移，**按它报的逐处订正**（含 `knowledge/docs/PROTOCOL.md`、`skills/akdagent-protocol/SKILL.md`、`tools/gen-github-readme.cjs` 自身）；
2. 订正草案后重跑三个生成器；
3. 再复跑该守卫，直到 `✅ 无漂移`。

## ⚠️ 两条 2026-10-06 踩出来的坑（都跟"文件清单"有关）

**① 守卫里别写死"要扫哪些文件"—— 扫目录。**

`check-tool-inventory.cjs` 原来写死 `['server/src/tools.ts']`：
- 漏了 `ace/tool-import.ts`（ACE 工具注册在那里，而且用**单引号** `server.tool('…')` ⇒ 正则也得两种引号都认）⇒ 少算一个，
  于是**文档里正确的名字被误报成「文档多」**；
- 后来又漏了新增的 `write-notes.ts` ⇒ 同一个症状再来一次。

⇒ 现在两个守卫都改成**遍历 `server/src/**/*.ts`**（dist 侧遍历 `server/dist/**/*.js`）。**新增注册文件不需要再改守卫。**

**② 往 `knowledge/docs/` 加文件后，必须重做脱敏副本。**

`check-package-assets.cjs` 会比对「真源份数 vs 副本份数」。加一个 `.md` 到 `knowledge/docs/` 就会变成 `真源 13 / 副本 12` ⇒ 报红。修法（注意目标是 `dist/knowledge`，**不是**它下面的 `docs`）：

```powershell
node tools/check-redaction.cjs --redact-to dist/knowledge --clean
```

**③ 同理：客户端 `electron/src/` 下的第三方构建（`vendor/**`）不进库，但必须落位。**
`electron/src/vendor/pdfjs/...` 由 `node tools/stage-pdfjs.cjs` 从 `server/node_modules/pdfjs-dist` 复制；
忘了跑 ⇒ `tools/check-pdf-render-wiring.cjs` 报红（**别指望打包时才发现**，那时用户拖 PDF 只会得到一句"渲染失败"）。

## vendored 第三方引擎（悦谱 Dolce · 识谱 OMR）—— 真源 · 复制 · 守卫

**真源在仓库外面**：内置识谱（"丢一张谱子图片进来，出 MusicXML"）的引擎是上游 **悦谱 Dolce**（**MIT**）。
我们**只往里拷产物、不编译它** ⇒ "真源 → 产物"这条链是**手工**的（没有 `tools/gen-*` 生成器）：

| 环节 | 位置 | 谁盯着 |
|---|---|---|
| 上游来源（人读） | `vendor/dolce-omr/SOURCE.md`：`https://github.com/lodebar2026/dolce` · commit `912447d` · v0.8.1 · MIT · 取法与构建命令 | 守卫 ②：**与下面那份机器可读来源逐字一致**（不一致就红，不是只打印） |
| 上游来源（机器读） | `vendor/dolce-omr/package.json` 的 `dolceRepo` / `dolceCommit` / `dolceVersion` | 同上 |
| 引擎产物 | `vendor/dolce-omr/dist-cli/*.js` + `rasterglyphs.json`（1.4 MB 字形表，**调用方自己读进来**）+ `models/*.onnx`（简谱那路的 PP-OCR） | 守卫 ①③ |
| 进包副本 | `dist/server-runtime*/dolce-omr`（`tools/build-server-runtime.cjs` 复制；**排除** `node_modules` 与符号链接） | 守卫 ①③④（打包布局**真跑一张图**） |

**纪律**：`vendor/dolce-omr/` 与 `dist/server-runtime*/dolce-omr/` 都是**产物，别手改** —— 上游更新时按
`SOURCE.md` 里的命令重取、重建，并把上面两处来源记录一起改。

### 守卫与闸门

- **`tools/check-dolce-vendor.cjs`**（**默认就跑**，五段判据）：① 关键文件齐（开发树 + 每份存在的打包 runtime）
  ② 来源可追溯（上面两份来源记录必须一致）③ bundle **真能 `import`** 出 `recognizeRasterSong` /
  `RasterGlyphLookup` / `scoreToMusicXml`，以及简谱入口 `omr.js` 的 `recognizeImage`
  ④ **用打包布局真跑一张谱子图** —— 优先用**打包 runtime 里的编译驱动**（`<runtime>/dist/omr/dolce.js`，
  它按自己的布局规则解析到 `<runtime>/dolce-omr`，顺带验证 runtime 那份**裁剪过的** `pdf-lib` / `pdfjs-dist`
  还在），退回 `vendor/dolce-omr`；断言"**至少认出 1 个音符**"，且产物里**没有 prolog `<!DOCTYPE`**
  （引擎会写那行 DTD，而我们自己的 MusicXML 导入器一律拒含 DTD 的文件 ⇒ 剥不掉就等于"我们自己的产物我们读不了"）
  ⑤ F1 闸门（见下）。
  · `AKD_SKIP_OMR=1` = 只做 ①②③（**会明确打印"已跳过真跑"**），给"就想快查文件齐不齐"的场合。
- **夹具** `server/tests/fixtures/omr/dolce-screenshot-en-1440w.png`（1440×900、264 927 B）：
  来自**上游 MIT 仓库**的 `docs/screenshot-en.png` 等比缩放（来源 / 许可 / `sha256` 见该目录 `README.md`）。
  ⚠️ 它有个**硬分辨率门槛**：同图缩到 1300 宽 ⇒ `stats.notes = 0`（整张不认），1360 宽才认 ⇒ **别再缩小**。
  ⛔ **用户那几首版权谱不许进仓库当夹具。**
- **`tools/omr-quality.cjs`**（F1 质量闸门，由临时件 `server/omr-compare.mjs` 收编而来）：
  **⚠️ 默认不跑** —— F1 = 我们的产物 vs **真值 MIDI**，而合成夹具**没有**真值；拿"我们自己识别的结果"当真值
  是循环论证，用户版权谱又不许入库 ⇒ **判据是显式开关**：
  `--truth <真值.mid> --xml <我们出的.musicxml>`（或 `--image <谱子图>` 先跑一遍），
  可选 `--min-f1 <百分数>` 当阈值（低于它 exit 1）；环境变量 `AKD_OMR_TRUTH` / `AKD_OMR_XML` / `AKD_OMR_MIN_F1`。
  **不传真值时它只解释用法、exit 0。** 口径沿用旧件（**别改**）：速度不作判据 · 真值每个轨与各种合并都试一遍 ·
  再按**小节数**把真值截到与我们同跨度（每小节 tick = `beats × ticksPerBeat × 4/beatType`）。
  `node tools/check-dolce-vendor.cjs --truth <真值.mid>` 会把 ④ 刚跑出来的那份 MusicXML 直接喂给它。

> 两份工具都登记在 `tools/guard-list.cjs`（`check-*.cjs` 自动收录；F1 闸门在 `TESTS` 里单列一行 ——
> 它不是 `check-` 前缀，且**默认不做判据**）。刷新《守卫一览》跑 `node tools/guard-list.cjs`。
> 开发侧的决策/实测台账在 `docs/识谱接入.md`（`docs/` **不进库**，只当工作记录）。
