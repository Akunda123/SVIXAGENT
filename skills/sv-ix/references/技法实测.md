# Note 技法（articulations）实测

## 0. 🆕 2026-09-20 IX 1.0.1 真机复核（4 条更正 + 1 条待复验）

> 复核方式：桥 `0.3.18` 在 **Instrument X 1.0.1**（空工程，轨未指定乐器）上跑只读 `run_script`。
> **⚠️ 先说结论上的限定**：这轮复核用的是**未指定乐器的轨**，它**不是**验证"按乐器矩阵"的有效地面（见下 C 条）
> ⇒ 下面 5 条**只对"未指定乐器的轨"成立**，按乐器的矩阵**仍需在指定了乐器的轨上复验**。

**A. 选区 API 的位置（更正）**
`selectNote` / `hasSelectedNotes` / `getSelectedNotes` **都在 `editor:getSelection()` 返回的选区对象上**，
**编辑器本身与 `getArrangement()` 的选区上都没有**（实测均为 `nil`）：
```lua
local sel = SV:getMainEditor():getSelection()
sel:selectNote(g:getNote(1))      -- ✅ 累加式：连调两次 ⇒ 选中 2 个
sel:hasSelectedNotes()            -- ✅ true
sel:getSelectedNotes()            -- ✅ table，`#` = 2（IX 上 `#` 正常，不必回落 getNumSelectedNotes）
```
⇒ **推论（重要）**：`getArticulationState().incompatible` 那条判据**我们能自己驱动**（先前记的"必须人手选中"作废）。
桥自己的取法也是这条：`get_selected_notes` 在 IX 上实测 `count = 2` 正确（`ed:getSelection():getSelectedNotes()`）。

**B. `getArticulationState()` 的真实字段（补全）**
返回表含 **5 个**字段：`incompatible`(table) · `smart`(bool) · `slurAvailable`(bool) · `active`(table) · `predicted`(table)。
原文只写了 `incompatible`。实测空选区时 `incompatible = []`；有选区时它列出**当前音符不能用的技法**。

**C. `getSupportedArticulations()` 在"未指定乐器的轨"上返回全集（限定）**
实测该轨返回 **8 项**：`Staccato · Tenuto · Accent · Slur · Tremolo · Breath · Trill Major · Trill Minor`。
⇒ **不能拿它当"某乐器支持集"** —— 得先给轨指定乐器；否则会得到"什么都能用"的假象，
且 `incompatible` 里会混进**跨族误报**（实测出现弦乐专属的 `C. Legno` / `Pizz.`，与原文的"跨族误报"警告一致）。

**D. `Note.getAttributes()` 键可能不含 `dynamic`（实测）**
IX 上实测键为 `articulationsFixed · articulations · muted` —— **没有 `dynamic`**（与原文"无技法时 dynamic 可能无/null"一致，
但注意它可能是**整个键都不在**，取值前要判空）。

**E. 待复验：`Trill Major` / `Trill Minor` 的"互斥由 `incompatible` 判定"这次没复现**
实测 `setArticulations({'Trill Major','Trill Minor'})` ⇒ **写入成功**（`writeOk=true`）、回读**两者都在**
（**"写入层不拦"✓ 复现**）；但 `incompatible` 返回的是 `['Staccato','Tremolo','C. Legno','Pizz.']`
—— **`Trill Major`/`Trill Minor` 并不在其中**，反而是 `active = ['Slur']`（宿主 smart 系统的判断）。
⇒ **§5.1.1 的互斥规律需要"指定了乐器的轨"再验一次**；在此之前不要把它当定论用。

> 🆕 **2026-09-20 补：上面这个「没复现」很可能是方法 artifact** —— 那次是**把 `Trill Major` 与 `Trill Minor` 同时设上**再读 `incompatible`，而 `incompatible` 的语义是「**还能不能再加**」（已设上的键不出现在其中：那次它报的 `Staccato`/`Tremolo` **恰好正是**与 Trill\* 冲突的项 ⇒ **判据本身工作正常**）。⇒ **正解是「只设一个再读」**（`setArticulations({'Trill Major'})` → 看 `incompatible` 里有没有 `Trill Minor`）。**仍待带乐器的轨复验**，但**不能说「互斥已被否证」**。

**F. 计算类接口在 IX 上也**有值**（补两条事实）**
- `SV:getComputedPitchForGroup(...)`（我们的 `sv_get_computed_pitch`）在 IX 乐器轨上**返回真实数值**（实测 8/8 非空、
  `attempts=1`）⇒ 工具描述里"（SV2 2.1.1+）"对 IX 同样成立（IX 属 SV2 家族）。
- `getComputedAttributes` 在 IX **能正常返回**（实测 10 个音符都报了），但乐器轨上 `phonemes` / `accents` / `languages`
  **恒为空** —— 这是**正常的**（没有声乐音符），**不是**"渲染前置条件没满足"⇒ 器物轨上看到空别去查语种兼容性。
- 另：`group:getNumPitchControls()/getPitchControl(i)` 在 IX 上可用（`sv_write_pit` 的曲线路线**实测在 IX 端到端可用**：
  写入后 `getComputedPitch` 的数值随之改变 ⇒ 曲线确实被渲染）。读点用 `pts[k][1]/[2]`（详见 **`sv-pit-art` 技能的「0.3.1 读回的确切形状」**）。
- ⚠️ **曲线只挂在「组」上，Note 级没有**：`Note:getNumPitchControls()` **不存在**（实测 `n/a`）；要数/取曲线只能 `group:getNumPitchControls()` / `group:getPitchControl(r)`，曲线**自身**的锚点用 `curve:getPosition()` / `curve:getPitch()`，**点值**才是 `getPoints()` 的普通二元数组。
- 🔴 **IX 侧音高曲线这套是宿主「暴力移植」实现、当前该处有 bug**（**具体表现未定位、上游是否修未知**）⇒ 与 SV2 的表现**不能假设一致**，**和弦音高线尤其不要当成「已验证」**（已登记为已知缺陷 **IX-005**，复检见 `tools/known-bugs.cjs --plan IX-005`）。⚠️ 另有一层是**实现侧**的：`sv_write_pit` 按**单声部骨架**画曲线 ⇒ 同 onset 的同伴音会被拉到骨架音高、和弦可能被压成同度，故桥 **0.3.20** 起、**且仅在 IX 上**，写入时返回 `chordHint` 如实警告（⛔ **SV1/SV2 都不提示**：SV1 走 attr 路线、逐音符属性**没有**共享骨架；SV2 的骨架是**既定设计** —— **IX 的参数编辑限制不许外溢到 SV**）。

> **结论优先**：`Note.getAttributes()` 返回 `{dynamic, muted, articulations, articulationsFixed}`，
> `articulations` 是**字符串数组**。`SV.articulationTypes` 运行时枚举不到（宿主常量不暴露），
> 但**从 `.ixp` 文件的 `attributes.articulations` 可提取实测值**（最可靠）。
> **技法随声库/乐器变化**（不同乐器支持的技法子集不同），无统一全量官方枚举。

## 0.5 🆕 2026-09-21 IX 1.0.1 **整轮复验**（17 轨 · 全管弦 + 1 条空乐器轨）

> 方式：用户在 IX 里给 **17 条轨**指定乐器（并刻意留 **1 条未指定乐器**作对照），桥 0.3.21 逐轨跑
> `getMainEditor().getSupportedArticulations()`（`--caps`，只读）与「**只设一个技法再读** `incompatible`」（`--matrix`）。
> 工具：**`node tools/probe-ix-articulations.cjs`**（`--caps` / `--matrix` / `--cleanup`）。

**A. ✅ §3.1 的 12 行支持矩阵逐条复现**（含 Tremolo/Trill 支持者名单），并补齐弦乐三件 —— 详见 §3.1 的复验注。

**B. ⛔ §0-C 更正（那条的前提本来就错）**：**真·未指定乐器的轨 = 0 项**，不是 8 项。
（机器可读的实测表在 **`references/articulation-matrix.json`**，那条对照轨在表里的名字就是 **`(未指定乐器)`**。）
- 实测对照轨（`未命名音轨 1`）`mainRef.database.name = ""` ⇒ `getSupportedArticulations()` = **`[]`**；`incompatible` 也**全空**。
- §0-C 说的"返回全集 8 项"那条轨，其 `mainRef.database.name = "Orchestral Piccolo 1"` ⇒ **8 项正是 Piccolo 的真实支持集**（= §3.1 #0）。
- ⇒ 新结论：**"8 项"不是通用全集**；**没乐器时宿主既不给支持集、也不算互斥状态**。

**C. ⭐ 方法更正（§0-A 的必要补充，不照做数据必错）**：`selectNote()` 与 `getArticulationState()` **只对「当前组」生效**。
- `selection:selectGroup(ref)` **不够**（只把组"选进选区"、不切编辑器当前组）：实测切完 `hasSelectedNotes()=false`、`smart` 读不到、`incompatible=[]`。
- 真正管用的是 **`editor:setCurrentGroup(ref)`** —— 该成员**存在**（2026-09-21 索引确认）；调它之后 `selectNote()` 才成功、`smart=true`、`incompatible` 才有值。
- 只切轨（`setCurrentTrack`）不切组同样读不到。⇒ **每换一个轨，都必须 `setCurrentGroup(该轨那一组的引用)`**。

**D. ⭐ 互斥图是「宿主全局规则」、与乐器无关（本次最大发现）**：17 条不同乐器的轨，同一技法下 `incompatible`
**只有一种签名**（逐条全文比对完全一致）；**唯一例外是空乐器轨 —— 它全空**。
⇒ `skills/sv-ix/SKILL.md` §2.4 与 §0 原先说的"跨族误报（木管轨里报弦乐 `C. Legno`/`Pizz.`）"**既不是误报、也不是 bug**：这张图**本来就是全局的**，
它按**技法之间的姿态冲突**作答、不按乐器过滤。⇒ §5.1.1 改为按**全局图**记，不再提"跨族误报"。

**E. ✅ §0-E 结案：`Trill Major ⇄ Trill Minor` 互斥坐实**（用正解"只设一个再读"）：
`setArticulations({Trill Major})` ⇒ `incompatible` 含 `Trill Minor`；反向同理。§0-E 那个"没复现"确系**方法 artifact**。

**F. 新发现 4 个「只在互斥图里出现」的隐式键**：`Open`（弱音开音，与 `Straight`/`Cup`/`Stem` 互斥）·
`Arco`（弓奏，与 `Pizz.` 互斥）· `Senza Sordino`（去弱音，与 `Con Sordino` 互斥）· `Center`（与 `Bridge`/`Fingerb.` 互斥）。
四者**都不在** `getSupportedArticulations()` 里 —— 它们是**隐式的默认/对立态**，只在冲突判定里现身。

**G. `articulationsFixed` 实测**：`setArticulations({...})` 之后 `getAttributes().articulationsFixed` **一律变 `true`**
（22 技法 × 17 轨全量如此）；且写入层**对任何组合都不拒绝**（22/22 写入成功、回读一致）⇒ 再次印证 §5.1.2「写入成功 ≠ 真实可用」。

**G-补（2026-09-21 落地工具时真机复测）**：**写空表 `setArticulations({})` 也同样置 `articulationsFixed=true`** ——
即「只要脚本碰过这个音符，它就变成**显式指定**（哪怕显式为空）」，宿主 Smart Articulation 从此不再自动决定它，
而 **API 没有任何清掉 `fixed` 的手段**（`getAttributes` 读得到、没有对应 setter 验证过；唯一干净退路 = Ctrl+Z 撤销，
或在 UI 里把音符/面板切回 Smart）。实测痕迹：对 10 个音符「写入 → 再写空表还原」，还原后技法确实清空（`[]`），
但 10 个音符的 `fixed` 仍为 `true`（其余 9 个未触碰的音符仍是 `false`）。
⇒ 两条纪律：① 批量写技法**默认 dry-run**、只覆盖少数音符（路线 A）；② `fixed=true && articulations=[]`
是**常见合法状态**，跳过它时别一律说成"已有显式技法"。

## 1. `getAttributes()` 结构（IX Note，实测）
```js
note.getAttributes()
=> {
  "dynamic": 0.6732852458953857,   // 力度 0~1
  "muted": false,                  // 静音
  "articulations": ["Staccato","Accent"],  // 技法数组（可 0~3 个）
  "articulationsFixed": true       // 技法是否"固定"（用户显式设=true，默认=null/false）
}
```
- 音符无技法时：`articulations:[]`, `articulationsFixed:false`, `dynamic` 可能无/null。

## 2. 实测技法全集（13 种，从 ixptest.ixp 提取）
```
Staccato, Tenuto, Accent, Slur, Breath, Tremolo, Trill Minor,
Scoop, Doit, Fall, Harmonics, Portamento, Stopped
```
| 技法 | 含义 |
|---|---|
| `Staccato` | 断奏（短促）|
| `Tenuto` | 保持音 |
| `Accent` | 重音 |
| `Slur` | 连音/圆滑 |
| `Breath` | 呼吸/换气 |
| `Tremolo` | 震音 |
| `Trill Minor` | 小颤音 |
| `Scoop` | 上滑推音 |
| `Doit` | 上滑/甩音 |
| `Fall` | 下滑音 |
| `Harmonics` | 泛音 |
| `Portamento` | 滑音（连滑）|
| `Stopped` | 阻塞/闷音（管乐特有）|

### 组合规律
- 单/双/三值组合：`["Staccato","Slur"]`、`["Accent","Slur","Fall"]`、`["Doit"]`。
- `Slur` 常作中间元素（连唱段 + 奏法）；滑音类（Doit/Fall/Scoop）常单用或与 Slur 组合。
- 顺序有意义（如 `["Staccato","Accent"]` vs `["Accent","Slur","Fall"]`）。

## 2.5 🆕 官方术语 ↔ 存储键（2026-09-21 从官方页核对）+ **Smart Articulation**

> 来源：[Instrument X: First Look](https://www.dreamtonics.com.cn/ix-first-look/)（Dreamtonics 官方新闻稿，2026-08-26）。
> **官方逐条描述与我们实测的支持集完全吻合**（见 §3.1 复验注）—— 这也算给我们的实测矩阵找了个第三方旁证。

| 官方说法（英 / 意） | 存储键 | 实测支持者（§3.1） |
|---|---|---|
| staccato · legato · tenuto | `Staccato` · `Slur` · `Tenuto` | 全部乐器 |
| **col legno** | `C. Legno` | 弦乐四件 |
| **sul ponticello**（靠琴桥） | **`Bridge`** | 弦乐四件 |
| **sul tasto**（靠指板） | **`Fingerb.`** | 弦乐四件 |
| pizzicato | `Pizz.` | 弦乐四件 |
| con sordino（弱音） | `Con Sordino` | 弦乐四件 |
| tremolo · major/minor interval trills · falls · portamentos · harmonics | `Tremolo` · `Trill Major`/`Trill Minor` · `Fall` · `Portamento` · `Harmonics` | 逐条吻合 |
| inhalation breath triggers | `Breath` | 木管 / 铜管 / 弦乐 |
| straight / cup / **harmon** mutes | `Straight` / `Cup` / **`Stem`** | Trumpet 1 · Trombone 1 |
| horn **stopped** notes | `Stopped` | Orchestral French Horn 1 |
| （官方未单列） | `Scoop` / `Doit` | 仅 Jazz Sax（Alto 1 / Tenor 1） |

**⭐ Smart Articulation（官方既有能力 —— 想"自动配技法"前必读）**：官方原文说技法面板可在
**automated「Smart Articulation」** 与 **per-note 手动**之间切换，且技法**可任意叠加**。
⇒ 与实测对上：**没显式设过技法的音符 `getArticulationState().smart = true`**；一旦 `setArticulations(...)`
⇒ `articulationsFixed = true`、`smart = false`（2026-09-21 全量实测）。
⇒ **也就是说：脚本写技法 = 关掉那个音符的「自动配技法」**。所以"要不要脚本按旋律走向自动配技法"先得定位：
**① 只覆盖少数音符**（其余留给 Smart，最贴官方设计）**② 全权生成**（铺满 `articulationsFixed=true`，脚本必须自己保证不写不支持、不写互斥）。

**另两条官方事实（顺带记）**：① **五个风格预设** = `performanceDirection`：`Adagio` / `Allegro` / `con Fuoco` / `Pop` / `Ballade`（工程文件里见 `voice.performanceDirection`）；
② **Dynamics Lane 会自动铺力度**（官方原话："automatically maps context-appropriate dynamics … based on pitch, note duration, and performance flow"）
⇒ 音符级 `dynamics` 曲线**不必全靠手画**，宿主本来就会给（`IX-002` 说的是"脚本写不进去"，是另一件事）。

## 3. 实测管乐声库（12 轨，从 ixptest.ixp 的 `mainRef.database.name`）

> ⚠️ **`.ixp` 里音符不在 track 的 `notes` 里**：`tracks[]` 只存轨道的 `mainRef`（含 `database` 声库名）和
> 指向 `library[]` 的 group 引用；**真正带音符的 NoteGroup 全在顶层 `library[]`**（每个带 `uuid`，track 的
> `groups[].groupID` 通过 uuid 引用它）。所以"每乐器技法"必须 **track → groups[].groupID → library[该uuid].notes** 桥接。

### 5.1 技法组合规律（从逐音符序列归纳）
- **`Slur`（连音）常作组合元素**：`Tenuto+Slur`、`Staccato+Slur`、`Tenuto+Breath` —— 表示"带连奏/呼吸的姿态"。
- **滑音类（Scoop/Doit/Fall）多与 Tenuto/Accent 组合**：`Tenuto+Scoop`、`Tenuto+Doit`、`Accent+Fall`。
- **Tremolo（颤音）是独立技法，单用**（Piccolo/Flute/Trumpet 上的第 5 个音符都是单 `Tremolo`）。
- **多值数组最多 4 项**：`Staccato+Tenuto+Accent+Fall`（Bassoon）。顺序有意义。

### 5.1.1 技法互斥矩阵（**宿主全局规则** —— 2026-09-21 在 17 轨上整轮复验）

> **读法（必须照做，少一步就读不到）**：`editor:setCurrentGroup(该轨那一组的引用)` → `selection:selectNote(音符)`
> （先确认 `hasSelectedNotes()=true`）→ `setArticulations({ X })` **只设一个** → 读 `getMainEditor().getArticulationState().incompatible`。
> ⚠️ 只切轨 / 只 `selectGroup` **都不行**（§0.5-C）；"两个一起设再读"**也不行**（§0.5-E）。
> **性质**：这张图**与乐器无关** —— 17 条不同乐器的轨在同一技法下**只有一种签名**（逐条全文比对一致），
> **唯一例外是空乐器轨（全空）** ⇒ 下表即**全集**，**不要再按"本组支持集"过滤**。

| 技法 X | `incompatible`（设了 X 之后，**还能不能再加**这些 ⇒ 即与 X 冲突的项） |
|---|---|
| `Staccato` | Tremolo · C. Legno · Trill Major · Trill Minor |
| `Tenuto` | C. Legno |
| `Accent` | （无）|
| `Slur` | Tremolo · C. Legno · Pizz. |
| `Tremolo` | Staccato · Slur · Portamento · C. Legno · Pizz. · Trill Major · Trill Minor |
| `Breath` | （无）|
| `Trill Major` | Staccato · Tremolo · C. Legno · Pizz. · **Trill Minor** |
| `Trill Minor` | Staccato · Tremolo · C. Legno · Pizz. · **Trill Major** |
| `Scoop` | Doit · Fall · C. Legno |
| `Doit` | Scoop · Fall · C. Legno |
| `Fall` | Scoop · Doit · C. Legno |
| `Harmonics` | C. Legno · Pizz. · Bridge · Fingerb. |
| `Portamento` | Tremolo · C. Legno |
| `Stopped` | （无）|
| `Straight` | **Open** · Cup · Stem |
| `Cup` | **Open** · Straight · Stem |
| `Stem` | **Open** · Straight · Cup |
| `Con Sordino` | **Senza Sordino** |
| `C. Legno` | Staccato · Tenuto · Slur · Portamento · Tremolo · Harmonics · Scoop · Doit · Fall · **Arco** · Pizz. · Bridge · Fingerb. · Trill Major · Trill Minor |
| `Pizz.` | Slur · Tremolo · Harmonics · **Arco** · C. Legno · Bridge · Fingerb. · Trill Major · Trill Minor |
| `Bridge` | Harmonics · C. Legno · Pizz. · **Center** · Fingerb. |
| `Fingerb.` | Harmonics · C. Legno · Pizz. · Bridge · **Center** |

**规律**：
- **冲突集中在"同音性 / 姿态"类**：`Staccato` ⇄ `Tremolo` / `Trill*`；`Tremolo` ⇄ `Staccato`/`Slur`/`Portamento`/`Trill*`；
  **`Trill Major` ⇄ `Trill Minor`（本次坐实）**；`Slur` ⇄ `Tremolo`。
- **表达性修饰与谁都不冲突**：`Accent` · `Breath` · `Stopped` 全空；`Tenuto` 只与弦乐的 `C. Legno` 冲突（持音 vs 木鱼声的姿态问题）。
- **铜管四个弱音态互斥**：`Straight` / `Cup` / `Stem` / **`Open`**（`Open` = 默认开音，只在图里现身、不在支持集里）。
- **弦乐三组开关组内互斥**：`Con Sordino ⇄ Senza Sordino`（弱音开关的两态）· `Pizz. ⇄ Arco`（技巧组的拨奏/弓奏）·
  `C. Legno` / `Bridge` / `Fingerb.` 之间互斥（奏法 · 弓位，`Center` 是弓位默认态）。
- ⚠️ **`incompatible` 里出现"跨族"项是正常的**（如木管轨上报 `C. Legno`/`Pizz.`）—— **这张图本来就是全局的**（§0.5-D），
  **不是**宿主乱报、**不是** bug，**别**再按"本组 `getSupportedArticulations()`"去过滤它（旧版那段说法已作废）。
- ⚠️ **写入层不拦任何组合**：`setArticulations({'Trill Major','Trill Minor'})` 照样成功并存 ⇒ **真实可用性只能以 `incompatible` 为准**。
- 🆕 **图上那 8 条"单向边"不是漏测**（2026-09-21 落地工具时核对）：`Straight`/`Cup`/`Stem → Open` · `Con Sordino → Senza Sordino` ·
  `Pizz.`/`C. Legno → Arco` · `Bridge`/`Fingerb. → Center` —— **全部指向 §0.5-F 那 4 个隐式默认键**。隐式键**没有自己的行**、
  也永远不会出现在任何乐器的支持集里（⇒ 永远不会被设上去），故反向边无意义。代码按**双向**判冲突（`a→b 或 b→a`），
  实际行为对称；把图打印成矩阵时别把这 8 格当成没测。。

### 5.1.2 关键教训：写入成功 ≠ 真实可用
- `setArticulations([...])` **几乎不拒绝任何组合**（宿主会照单全收、或按自身优先级重排）。
- **真实可用性/互斥由 `getArticulationState().incompatible` 权威判定**。
- 所以"某组合能不能用"要**选中音符后读 `incompatible`**，而不能靠"写入是否报错"来判断。

### 5.2 弱音器（mute）+ 技法组合（确认同数组、可叠加）
弱音器与技法**在同一个 `articulations` 数组**里，组合顺序为 **技法在前、弱音器在后**：
- `["Staccato","Stem"]`、`["Tenuto","Cup"]`、`["Stem"]`（单独弱音器）
- 弱音器选项：`Straight`（直音）/ `Cup`（杯形）/ `Stem`（梗形）。
- **弱音器仅铜管有**（小号/长号/圆号/大号），木管（Piccolo/Flute/Oboe/Clarinet/Bassoon/Sax）与 Tuba 无。
- 注：上述逐轨只点到 `Stem/Cup`；`Straight` 是否铜管全支持需另测。此问题需**运行时逐乐器枚举 `getSupportedArticulations()`** 才能真正判全，`.ixp` 能确认的只是"被点过的"。该枚举在 `knowledge/docs/InstrumentX-API枚举.md` 的「13.4 常量 / 宿主环境」里提到宿主常量不暴露，故取 `getMainEditor().getSupportedArticulations()`（本文件「4. IXP 里 note 的技法存储」已有该方法）。

### 5.3 弦乐演奏开关（checkbox）——多组「单选互斥」开关，可跨组叠加，共用同一数组
Instrument X 弦乐（Violin/Viola/Cello/Contrabass）为每个音符渲染一组 checkbox（勾选框）开关面板，
每个开关组是**单选互斥**，不同组之间**可叠加**。底层与通用技法、铜管弱音器**全部存入同一个
`note.getAttributes().articulations` 字符串数组**（并无独立字段）。

**开关组结构（存储键 ↔ UI 中文，实测确认）：**

| 维度 | 单选选项（UI 中文 → 存储键） |
|---|---|
| **奏法组** | 常规(默认→无键) / 弓奏 `C. Legno` / 琴桥 `Bridge` |
| **技巧组** | 常规(默认→无键) / 指板 `Fingerb.` / 拨奏 `Pizz.` |
| **弱音**（独立开关）| 无弱音(默认→无键) / 有弱音 `Con Sordino` |

> 另外每一组还能再叠加**通用奏法技法**（断音/持音/重音/连音/滑音/震音/泛音/气音/下滑等，
> 见 §3.1 每乐器支持的技法全集）。这些是有别于上述三组的独立可选项。

**一个音符的 `articulations` = 各维度"选一/选默认"之和**，例如：
- `["Fingerb."]` = 常规 + 指板（技巧组选了指板）
- `["Con Sordino","Fingerb."]` = 常规 + 指板 + 有弱音（弱音与技巧组**跨组叠加**）
- `["Staccato","Bridge"]` = 断奏技法 + 琴桥（奏法组选了琴桥）

**实测组合行为（2026-08-30，桥 `setArticulations` 后回读）：**
- `setArticulations(['C. Legno','Pizz.'])` → 回读 `["C. Legno","Pizz."]` —— 弓奏 + 拨奏并存（宿主允许）。
- `setArticulations(['Pizz.','Staccato'])` → 宿主自动重排为 `["Staccato","Pizz."]` —— **通用奏法排前**，弦乐开关排后。
- 与铜管"技法在前、弱音器在后"是**同一套排序规则**。

**结论**：弦乐音符的 `articulations` 是"奏法组 + 技巧组 + 弱音 + 可选通用奏法"的拼装数组。
- **组内单选**（每组只留一个），**组间可叠加**（不同维度的键可共存）。
- **宿主会重排**：通用奏法（Staccato/Tenuto/Accent…）排前，弦乐开关（C. Legno/Bridge/Fingerb./Pizz./Con Sordino）排后。
- `getSupportedArticulations()` 对 Viola 返回 16 项，其中弦乐专属 5 项（C. Legno/Bridge/Fingerb./Pizz./Con Sordino）。

> ⚠️ 弦乐开关的中文标签（弓奏/琴桥/指板/拨奏/有弱音）**不在 `SV.T()` 也不在 `server-translations/zh-cn.txt`**
> （后者只含乐器名翻译）。该中文界面是 Instrument X 弦乐面板自渲染，底层键仍为上述英文字符串。
