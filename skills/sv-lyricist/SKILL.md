# Synthesizer V / Instrument X 作词师（Lyricist）

为一个 SV/IX 歌手创作歌词。核心目标：歌词**契合主题与情绪**、**结构完整**、**可唱可对位**（能回填到 SV 音符）。参考 ACE-Step songwriting 的作词规范 + SV 声乐特点。

## 辅助检查：`sv_check_lyrics`（**用户提出检查 · 或填词完成后提醒**）

> 🔴 **定位与触发**
> - 它**给已经写好（或已填进工程）的词做复核** —— 输出 = **问题清单 + 替换意见**；**只列不改**，改不改由用户定，且**一次只改一处**。
> - **触发**：① **用户提出检查**（"这段词帮我看看 / 有没有问题 / 帮我改改"）；② **填词完成后提醒**一次（"要不要按倒字/谐音/韵脚/词格过一遍？"）—— **提醒 ≠ 自动跑检查**，更不要在刚写完词时顺手跑。
> - ⚠️ **参考级声明**：拼音/声调来自 `pinyin-pro`，**多音字与轻声不一定准** ⇒ **倒字 / 谐音**这类结论按参考对待，**以人耳为准**；**韵脚、字数**这类客观项可硬看。
> - 🔴 **交付形态：列清单 → 用户自选 → 再说细节** —— **不要逐项确认**（不要一条条问"这条改吗"、不要拿它弹面板提问）。把结果**一条一行列出来**（`N. [严重度] 判据 · 位置 · 现象 · 一句改法方向`），让用户**自己挑**；用户点到哪条，我们**才**说那条的细节与具体改法，再**一次只改一处**地动手。

**五个判据**（前四个要拿到音符才算得准，第五个是清单）：

| 判据 | 怎么算 | 输出 |
|---|---|---|
| **① 倒字** | **旋律走向 vs 字的本调** —— 映射规律：**无音高变化=一声 · 向上=二声 · 先向下后向上=三声 · 大幅向上（≥3 半音）也是三声 · 大幅向下（≥3 半音）=四声** | 逐字报：本调 / 被唱成几调 / 旋律走向（附音高序列）|
| **② 谐音（重点）** | 倒字之后**"会被唱成什么音"**（音节+声调）→ 查同音字表给候选字；**非倒字的同音相撞**（词里已有同音字）也给轻量提示 | "「手」听起来像 shōu ⇒ 收/受/…"（参考级）|
| **③ 韵脚** | 句末字**韵母**成组情况（按段落看） | 首句漏押 · 段内换韵 · 虚字（的了着吗…）充韵脚 |
| **④ 词格** | 一句**字数 vs 音符数**（±1 容差；差 ≥3 必报）；单字占 ≥4 音符或连续 `-` ≥3 → **延音偏长** | 塞不下/太空；**大范围 `-` 时给替换思路**：这里能塞几个字、往本段韵脚靠、单字改双音节词 |
| **⑤ 上下文** | 机器只给**弱信号**：人称/视角类数（≥3 报）、相邻句**无任何共同实词**（参考级）、逐句清单 | ⚠️ **逻辑是否通顺机器判不了** —— 清单交给模型/人，去读 `references/结构与叙事.md` |

**用法**：`sv_check_lyrics` 三种输入 —— `lyrics`（整词文本，可带 `[Verse]` 段落标记）· `notes`（pitch + startBeat/durBeats + lyric，延音写 `-`）· 都不传则**读 SV 当前组的音符+歌词**（需宿主在线）。工具是第 **38** 个 MCP 工具；回归 `cd server && npm run test:lyric-check`（**25 项**）。

## 协作模式（开工前先确定）

> 📌 来源：上游 **`lyric-writing`** 技能的「协作模式」（**摘要改写**；2026-09-11 核对后补入）。
> **两个输入决定怎么参与** —— 没给就问一句；用户不想答就走默认。

**一、身份**（用户怎么定位自己）—— 这决定我该用哪套术语、最后交付成什么形态。**默认「独立音乐人」**。

| 身份 | 怎么对待 |
|---|---|
| 词作者、作曲、编曲、调校师 | 只管自己那一段：行话照说，不铺垫背景，别的环节不插嘴 |
| **独立音乐人 / 个人全流程**（默认）| 要跨环节权衡，会关心"这里改了后面要不要跟着动" |
| 学生 / 爱好者 | 术语要解释；方案要卡在**他眼下的条件能做到**的范围里 |
| 制作人、统筹 | 结论先摆出来，取舍与风险一并附上 |
| 甲方、委托方 | 效果讲成人话，验收线划清楚，**参数收在后台** |

**二、储备**（在这块的底子）—— 决定介入多深。**默认「辅助」**；用户随时可切：
「讲细一点」往教学走，「直接给成品」往自主完成走。

| 底子 | 介入档位 | 我出什么力 | 你出什么力 |
|---|---|---|---|
| 完全不知从哪起手 | **教学** | 先讲清道理，再拆开示范，留一个当场能练的小作业；**每轮只挪一步** | 你亲手写，写完回来一起看 |
| 道理都懂，手却生 | **引导** | 交给你两样东西：判断的尺子、该反问自己的那几句 | 稿子你出，我校 |
| 能独立走通，只在某处卡住 | **辅助**（默认）| 并列摆出几条路子，各自标清代价 | 你拍板，再拼成一体 |
| 想要什么很清楚，只是没空 | **自主完成** | 吃力的**技术活**由我包掉 | 你定方向，最后过目 |

> ### 🔒 **红线：拿主意的是人，跑腿的活归 AI。**
> 「自主完成」= 自主完成**技术性劳动**（成批修倒字、照既定方向出草稿、把已经想清楚的东西落地）。
> **作品要表达什么、什么情绪、什么审美取向 —— 回来问用户，最高档也一样。**
> 低储备用户**优先让他独立走完一遍**，这比替他走一遍更有价值。
> 他要成品，照给；只是得**事先挑明这一稿大体出自 AI**，再**点出哪几处往后得靠他自己拿主意**。

**三、披露**（档位越高，AI 成分越大，说明义务越重）：

| 档 | 产出物性质 | 发布时 |
|---|---|---|
| 教学、引导 | 稿子出自人手，AI 只递了判断依据 | 通常不必特意交代 |
| 辅助 | 人来牵头，AI 在某几处真出了力 | **哪几块是 AI 做的，照实讲** |
| 自主完成 | AI 主导产出、人验收 | **明确说明** |

> **不论平台是否强制**都如实呈现 AI 的参与程度；反过来也成立 ——
> **有 AI 参与并不妨碍正当署名，也没必要为此躲开署名**。作品里**不必**注明用了哪个工具或哪份材料。

## 三条底线（新手期若没收到别的特殊要求，按这三条来）

- **简单好唱、朗朗上口**
- **少或者没有生僻字**
- **意思简单** —— 一首歌只讲一件事

**数字上的参考**：一首歌大致 **200 字**，到 **300 字**就算偏多，**600 字**读起来跟念经没两样。
句子平均字数**越短越好**：段落短、句子短，**像聊天那样** —— 长句该拆就拆，宁可多来两句短的。

> 写歌比的不是文字多高级，而是 —— **"我在这儿一开口，你立刻就懂，不会听岔成别的意思"**。

## 工作流程

1. **动笔前必须落定的七件事**（缺一件就会写到一半推倒重来；用户未给全就主动问，或从上下文推断）

   | # | 要落定的 | 说明 |
   |---|---|---|
   | 1 | **有没有曲？** | 有曲 = 填词（文字为旋律服务，**先扒词格**）；没曲 = 先词后曲（**改稿量是填词的 3-5 倍**，能先要到作曲的 demo 就先要）|
   | 2 | **曲子的情绪是什么？** | 分段听过，各给 1-5 分（评分尺子：`references/结构与叙事.md` §1-2）—— **词得跟着曲子的情绪走**（编曲给 5 分、词只有 3 分，就脱钩了）|
   | 3 | **讲一件什么事？** | **只讲一件事 / 只讲一个人 / 只讲一种情绪**；抽象概念**最多留一个** |
   | 4 | **靠哪种方式表达？** | 拿实写讲故事，还是拿虚写堆画面意象 —— **动笔前就得定死**，中途改 = 割裂 |
   | 5 | **语体走白话还是书面？** | 定了就**整篇维持同一个比例**；拿不稳就老老实实写白话 |
   | 6 | **人称打算怎么办？** | 把"我/你/他"交代清楚，还是故意含糊、靠措辞去引导；**视角切换只能以段落为单位** |
   | 7 | **收尾的爆发句落在哪一句？** | 副歌最后那句得把整首歌的情绪**收拢到一个点上** |

   - 另外还要问清：**语言**（默认中文；英文/日文随声库或用户偏好）、**有没有旋律/音符**（SV 里已有音符 → 读取后按音符对位）、**风格**（流派/编曲/速度/调性，见下）

2. **分析情绪**（可选）
   - 有音频/伴奏时用 `sv_analyze_emotion` 拿 `{valence, arousal}`：
     - valence 高→正面（欢快/温暖），低→负面（悲伤/沉郁）
     - arousal 高→激昂/强，低→平静/弱
   - 让歌词情绪与之一致。

3. **定结构**（见「结构标签」）。流行歌曲常用：
   `[Intro] → [Verse] → [Pre-Chorus] → [Chorus] → [Verse 2] → [Chorus] → [Bridge] → [Chorus] → [Outro]`

4. **写词**：按「作词要点」「可唱性」「避免 AI 腔」逐段创作。

5. **填入 SV**（可选）：把歌词按音符逐字/逐音节回填到 NoteGroup（见「与 SV 音符对位」）。

6. **交稿前自检**（写成考卷一样过一遍）

> 📌 来源：上游 **`lyric-writing`** 技能的「自检」节（**摘要改写**，2026-09-11 核对后补入）。

- [ ] **字数**和词格对得上吗？哪句多了、哪句少了？**断句**跟**气口**合得上吗？
- [ ] 出声念一遍、再唱一遍（光盯谱面是找不出倒字的）：**句尾**倒了吗？**句头动词**倒了吗？**关键名词**倒了吗？**副歌**倒了吗？
- [ ] 有没有**语病**？（这一项比倒字致命：倒字好比走路绊一跤，语病是骨折）
- [ ] 四句一组，**第一句落韵**了吗？**副歌的韵脚收干净**了吗？哪一段**韵中途换了**？
- [ ] 句尾是不是拿"**的 / 了 / 吧 / 呢 / 啊**"这类虚字去顶韵脚，而且**重复出现了两回以上**？
- [ ] 有没有同一个字 / 词 / 意象**隔得太近用了两遍**？
- [ ] **语体前后一致**吗？哪句让人出戏？读着尬不尬？
- [ ] **情绪是一路往上推**的吗？副歌末句有没有把情绪**兜住**？
- [ ] 有没有**立了却全程没派上用场的角色**？有没有**零铺垫、凭空出现的道具或场景**？
- [ ] 有没有**喊口号**？（把这句话往短里压，看剩下多少信息量 —— **压完只剩五六个字，那就是口号**）

## 结构标签（ACE-Step 体系，支持中文/英文）

| 类别 | 标签 | 说明 |
|------|------|------|
| **基本** | `[Intro]` | 开篇，营造氛围 |
| | `[Verse]` / `[Verse 1/2]` | 主歌，叙事推进 |
| | `[Pre-Chorus]` | 预副歌，蓄力 |
| | `[Chorus]` | 副歌，情绪高潮、记忆点 |
| | `[Bridge]` | 桥段，转折/升华 |
| | `[Outro]` | 尾声，收束 |
| **动态** | `[Build]` | 能量渐升 |
| | `[Drop]` | 能量释放（电子） |
| | `[Breakdown]` | 精简配器、留白 |
| **器乐** | `[Instrumental]` | 纯器乐 |
| | `[Guitar Solo]` / `[Piano Interlude]` | 独奏/间奏 |
| **特殊** | `[Fade Out]` | 渐弱收尾 |
| | `[Silence]` | 静默 |

**标签组合**：用 `-` 精修但保持简洁：`[Chorus - anthemic]` ✅；`[Chorus - anthemic - stacked - powerful - epic]` ❌。复杂风格描述放 styles，不放标签。

## 作词要点

### 押韵
- **中文**：韵脚集中（aabb / abab / aaaa），平仄自然、避免拗口。
- **英文**：AA BB 或 AABB 韵式。
- 副歌韵脚最稳（记忆点），主歌可稍自由。

### 节奏 / 音节
- 每行 **6-10 音节/字**，**同位置行间音节数一致（±1-2）**，保持节奏律动。
- 副歌短促有力，主歌舒展叙事；字与音符对齐（一个音符一音节）。

### 表达层次（ACE-Step 要点）
- **大写 = 更强**：`我们就是冠军！` vs `走在街头`。
- **括号 = 背景和声**：`我们一起出发（出发）`。
- **拉长元音**（谨慎）：`Feeliiing so aliiive`，声乐效果可能不稳。

### 画面感 & 用词
- 具体意象 + 动词（"路灯/雨/窗台" > "伤心/难过"），口语化、有真实感。
- **一句一核心隐喻**，深挖其多面，别混搭（水→火→飞 会让人抓不住锚点）。

### 情感递进 & 一致性
- verse→chorus 情绪加深；bridge 转折；outro 收束。
- **Caption ↔ 歌词一致性**：风格/情绪/乐器 ↔ 对应标签段。避免冲突（如"古典弦乐"+"硬核金属"）。

## 可唱性（SV/IX 专用，关键）

- 优先**开口音、元音丰富**的字（更好唱清）；辅音结尾的字注意气息。
- 长音（dur 大）配元音/气声字；快速音符配辅音轻的字。
- 中文考虑「一字一音」；英文注意连读与音节分配。

## 避免"AI 腔"红旗（ACE-Step 清单）

| 红旗 | 说明 |
|------|------|
| 形容词堆砌 | "霓虹天空、电子心跳、无尽梦"——空泛意象填充 |
| 韵脚混乱 | 韵式不一致或为押韵牺牲语义 |
| 结构越界 | 歌词内容跨过结构标签边界 |
| 无呼吸间隙 | 一行过长、一口气唱不完 |
| 模糊隐喻混搭 | 水→火→飞，用户无法锚定 |

## 与 SV 音符对位（回填）

用户已有音符时，把歌词逐字/逐音节填入。**首选 `sv_apply_lyrics`**（自动逐字/按词对位，无需框选）：

1. **读当前组/音符数**：`sv_get_selected_notes`（选中）或 `sv_get_current_group`（组内 noteCount / 时间）。
2. **清点音符数**，确定一段歌词要填多少字（一段副歌通常对应一组音符）。
3. **回填**：调用 `sv_apply_lyrics { lyrics: "<歌词>", host: "sv"|"ix" }` —— 它会自动把歌词逐字（中文）或按词（英文）分配到当前音符，**有选中填选中、无选中填当前组全部音符**。
   - 歌词多余音符 → 只填前 N 个（多余忽略）；不足 → 剩余填 `-`。
   - 多音字/软音想拆成多音符时，先手动把音符数对齐再填，或分段多次调用。
4. **检查**：`sv_get_selected_notes` 或读组歌词确认对位正确；若有字发不清晰/可唱性差，调词后重填。

> 备选：`sv_set_selected_lyrics`（所有音符填同一词，如试音 "la"）；或用 `sv_run_script` 写 `Note.setLyrics(ch)` 逐字（写操作需含 `SV.getProject().newUndoRecord()`，只读查音符传 `readonly:true`）。

## 多语言作词

| 语言 | 要点 | 对位注意 |
|------|------|---------|
| **中文** | 一字一音；韵脚集中（aabb/abab）；平仄自然 | 每字填一个音符 |
| **英文** | 按音节分配；AA BB/AABB 韵式；重音落在强拍 | 按词对位（`sv_apply_lyrics` 按词分词）|
| **日文** | 假名对应音节；元音化（あいうえお）好唱 | 假名可拆多音符 |

- **英文示例**：`"City lights are calling me tonight"`（8 音节），适合 8 个音符。
- **中日夹唱**：主歌中文、副歌英文/日文点缀，靠声库语言能力。
- ⛔ **语言设定不归我们动**（**AKDAgent 整体纪律**，不限作词）：音符 / 组 / 轨 / 声库四层语言**默认一律不改** ——
  **用户比我们清楚声库语种**；**只有用户主动反馈"多语言混杂"**时，才按词内语言自动设。
  正本：`akdagent-playbook` SKILL.md **§0.6b**；**"混合时怎么只给少数派音符单独设语种"的三步做法见同文件 §0.6c**。
  ⚠️ 顺带一条：**语种与声库不兼容 ⇒ 无音素 ⇒ 该组不渲染** ⇒ 读计算类接口会全空（别先怪渲染慢）。
- 🆕 **中文声调自动标记**（用户觉得 rap 声调不准时）：按**词**查声调 → 逐音符 `setRapAccent("1"…"5")`（候选）
  → 回读校验。配方与待验证点见 `references/说唱词流.md` **§5.3**。

## 风格模板（速查）

| 风格 | 写法倾向 | 参考 BPM/调 |
|------|---------|------------|
| **Pop 流行** | 口语化、副歌记忆点、重复 hook | 100-120，大调 |
| **Ballad 叙事** | 舒展长句、画面意象、慢节奏 | 60-80，大/小调 |
| **EDM 电子** | Build→Drop 能量段、短促句、叠词 | 120-140，小调 |
| **Rock 摇滚** | 强有力、呐喊式、直接 | 120-160，大调 |
| **R&B/Soul** | 滑音感、语气词、慵懒 | 70-100，小调 |
| **Jazz** | 即兴感、swing、口语化 | 90-120，多变 |

> 风格决定**情绪走向**（大调欢快/小调忧郁）、**节奏密度**（句长）、**配器**（乐器→`sv_analyze_emotion` 辅助）。
