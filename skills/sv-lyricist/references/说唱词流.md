# 说唱词流（rap flow）

> 触发：用户说要**说唱 / rap / 嘻哈 / flow / 双押 / 三押 / 快嘴 / 一句话怎么塞进去**，
> 或在 SV 里把音符组切成说唱（`musicalType = "rap"`）后不知道词该怎么写。
> 本文只管**词与词流**；音符/参数/工具那一侧见 **§5 与 SV 的对接**。

---

## §1 先分清两个词：flow ≠ 内容

| | 说的是什么 | 怎么写 |
|---|---|---|
| **flow（词流）** | 字**落在拍上的位置与密度** —— 是音乐性的东西，和鼓点咬合 | 数拍子、排格子（§3） |
| **内容** | 讲了什么事、什么情绪、什么画面 | 走 `结构与叙事.md` / `意象与修辞.md`，**与流行歌词同一套标准** |

⚠️ 最常见的翻车：**只把流行歌词写快** —— 字数一密、flow 全是正拍、韵脚不看拍点，结果听着像**念课文**，
不是说唱。**说唱的词是"打点"的**：先有格子，再往里填字。

---

## §2 中文说唱的三条硬约束（和英语不一样，别照搬）

1. **一字一音**。中文没有连读吞音，一个汉字基本吃掉一个音符位（英语一个词可以糊在多个 16 分上，中文不行）。
   ⇒ **句子长度 = 音符个数**，写词时要能数出来（数法与断句见 `咬字与倒字.md` §1-2）。
2. **声调被压平，同音歧义变大**。说唱音高变化小、语速快 ⇒ 说话时靠声调区分的东西到了歌里全靠**上下文与咬字**。
   例：「事实」与「事时」、「石头」与「湿透」在快 flow 里极易听混。
   ⇒ 快段**优先选声母清晰、不带生僻音的字**；歧义句要么换词，要么**放慢/留白**给它一个气口（分级与改写手段见 `咬字与倒字.md` §3-4）。
3. **韵脚要落在拍上**。押韵在说唱里不只是"韵母相同"，还是**节奏事件**：
   同一韵脚落在**正拍**上会"砸"得很实，落在**切分/反拍**上则显得"滑"。
   ⇒ 定韵（`押韵与韵脚.md` §2）之后，还要**给韵脚字安排拍点**：重要段落把韵脚压在正拍。

---

## §3 flow 的四种基本型（4/4 一小节，`x` = 一个字，`-` = 空拍/延音）

> 写法：把一小节切成 8 个八分音符格（每格半拍），下表的 `x` 就代表"这个格上有字"。
> 不同的型 = 不同的**疏密与重心**；换型就是换段落气质。

| 型 | 八分格示意 | 感觉 | 常用位置 |
|---|---|---|---|
| **正拍推进** | `x - x - x - x -` | 稳、像走路 | verse 主段、叙述句 |
| **切分/后十六** | `- x x - x x - x` | 有推背感、往前赶 | pre、情绪起势 |
| **三连音** | `xxx xxx xx-` | 密、炫技、容易糊 | 炫技句、短促收束 |
| **拉伸/半速** | `x - - - x - - -` | 宽、有空间 | hook、punchline、句尾 |

三条排 flow 的经验（当尺子用，不是定律）：

- **密度要变化**。整段都是密 = 没有重点；整段都稀 = 没劲。惯例是**稀 → 密 → 拉宽收尾**。
- **气口是标点**。句子之间必须留空拍（半拍到一拍），否则听感是"上不来气"，也听不出句读。
- **换型要有预兆**。换 flow 前一小节通常先把**韵脚压正拍**，让听众的耳朵先安定，再换。

**字数档位**（每小节的字数，凭经验，按语速与风格浮动很大，**别当硬指标**）：

| 档 | 字数/4-4 小节 | 适用 |
|---|---|---|
| 慢（half-time） | 4~8 | 叙事、情绪、hook |
| 中（主流） | 8~12 | verse 主段 |
| 快（double-time） | 16~24 | 炫技段，**必须句句检查咬字** |

## §4 段落角色（说唱的"起—压—炸"）

| 段 | 常见长度 | 词流 | 干什么 |
|---|---|---|---|
| Intro / ad-lib | 2~4 小节 | 稀疏、碎片 | 立气场；短句、口头语 |
| Verse | 8 或 16 小节 | 中档为主，**中段加密** | 讲事、铺垫；**每一句都要有新信息** |
| Pre / build | 4 小节 | 提速、韵脚加密 | 把情绪顶上去；常用切分或三连音 |
| Hook / 副歌 | 4 或 8 小节 | **拉宽、repetition** | 记忆点；短句 + 重复 + 韵脚压正拍 |
| Bridge / breakdown | 4~8 小节 | 突然变稀或停顿 | 换视角/换情绪；给下一轮 hook 蓄力 |

- **"起—压—炸"**：前 4 小节把话说清（稀）→ 中 4 小节压密度（密）→ 后 4 小节放 punchline + 留白（拉宽）。
- Hook 的写法与流行歌一致（重复、短句、措辞升级），看 `结构与叙事.md` §1-2。
- **punchline 只留一句**。一段里塞三个"金句"，听众一个都记不住。

## §5 与 SV 的对接（特有，动参数前看这一节）

### 5.1 让宿主按说唱处理

- 音符 / 组的 **`musicalType`** 设为 `"rap"`（`get/setMusicalType`，可切回 `"sing"`）。
  ⚠️ 非 API 途径（UI 里操作）在 **SV1 上是"自动说唱"**，API 可以造出**手动说唱**。
- **`rapAccent`**（重音档，取 `"1"`~`"5"`）：**UI 层限"仅中文音符、仅 rap"** —— API **不校验**（拉丁词 + rap、中文 + `sing` 都能写进去并读回），
  ⇒ 写之前自己判：**`musicalType == "rap"` 且该音符是普通话**。

### 5.2 语种（⛔ **AKDAgent 整体语言纪律**，不只说唱）

> 📌 **正本：`skills/akdagent-playbook/SKILL.md` §0.6b**（默认不改语言、语言链、何时才动、以及"不兼容⇒无音素⇒不渲染"）。
> 本节只说**说唱场景下**这条纪律的后果，不重复立规。

- ⛔ **默认不动任何音符 / 组 / 轨语言**；**只有用户主动反馈"多语言混杂"**时，才按词内语言自动设。
- 说唱里最容易撞上的后果：**语种与声库不兼容 ⇒ 无音素 ⇒ 整组不渲染** ⇒ `sv_get_computed_attributes` 读到全空。
  快段音素密度高，**语种错了不只是"口音不对"，而是根本没有音素**。

### 5.3 自动标记声调（**用户认为"rap 声调不准"时用**；2026-09-18 用户提出）

**触发**：用户说"这段说唱**声调 / 语调不对**""听起来像别的字""帮我把声调标一下"。

**思路**：中文说唱的语调是**跟着字调走**的 ⇒ **先查每个词的普通话声调，再按声调给音符标记**，让宿主按声调算语调。

> ⚠️ **前提**：**说唱本来就没有"固定音高"** —— rap 音符不按固定音高唱，
> 音高就是**由声调 / 语调决定的**（`musicalType="rap"` + `rapAccent` 声调 + 宿主算出的 `rapTone`/`rapIntonation`）。
> ⇒ **不要**用"要不要固定音高"来问用户，也**不要**拿 `setPitchAutoMode` 当说唱开关。

**三步**

1. **取词**：读当前组所有音符的歌词（桥 op `get_melody_notes` 的 `notes[].lyrics`，索引 **0 起**）。
2. **查声调**：把中文词按**词**（不是按单字）转成带声调的拼音 —— 例如 `pinyin('中国', { toneType: 'num' })` → `zhong1 guo2`。
   - 🎁 **捷径**：如果歌词本身就是**带调的拼音**（`nǐ hǎo` / `ni3 hao3`），**声调已经在词里**，直接读出来即可 —— **不用查词典**。
   - ⚠️ **必须按词定音**：多音字（行/重/长/还/得/了…）按单字查会错，**这是这一步唯一的坑**。
   - ⚠️ **拼音 / 罗马字写的词不是英语**：判语种要按语义（带调号或 `ni3` 式数字 ⇒ 中文；`tsu`/`shi`/长音/`-masu` ⇒ 日文罗马字），**不要把拉丁字母一律当英文** —— 判错语种，音素就没了，标签也没意义。做法见 `akdagent-playbook` **§0.6c**。
   - 词典两条路：**① `pinyin-pro`（npm，纯 JS、离线、带声调数字、能按词定多音字 —— 推荐）**；
     **② 内置精简表**（零依赖，但多音字只能取最常见读音，需接受少量误差）。
     两者都**完全本地**，符合"客户端不出网"。
3. **标记**：逐个音符写入（**先 `Project:newUndoRecord()`**），**写完必回读**。
   - ✅ **主用 `Note#setRapAccent(<声调>)`** —— 官方文档：*"rap accent is only used in Mandarin Chinese where there are **five accent types (1, 2, 3, 4, 5)**"*；
     **这 5 档就是五个声调 —— `1` 阴平 · `2` 阳平 · `3` 上声 · `4` 去声 · `5` 轻声**。
     **真机已验证（SV2 2.2.1）**：写 `"3"` 回读 `"3"`、写 `"5"` 回读 `"5"` ⇒ 直接用。
   - 备选 **`setAttributes({ rTone = <声调> })`**：**真机也验证可写**（写 4 回读 `4.0`），但它与 `rapAccent` 是**两个独立字段**（同写 `accent="5"` 与 `rTone=4` 各自保留），**`rTone` 在 UI 上对应什么还没确认** ⇒ **除非用户明确要动 `rTone`，否则走 `setRapAccent`**。
   - 回读：`Note#getRapAccent()` / `getAttributes().rTone`；渲染后还可用工具 `sv_get_computed_attributes` 看**宿主算出来的** `rapTone` / `rapIntonation`。
   - 写入前 `getAttributes()` 里没有 `rTone` 键是正常的（**只返回写过的键**）。

**✅ 已验证（2026-09-18 真机 · SV2 2.2.1 · 游离音符，未动工程）**：`setRapAccent("1"…"5")` 可写可回读；
`setAttributes({rTone=4})` / `{rIntonation=2}` 也确实写入（回读 `4.0` / `2.0`），但与 `rapAccent` **互相独立**；
`setLanguageOverride` 与 `setAttributes({languageOverride=…})` 是**同一字段**（写完 `getLanguageOverride()` 同步变）。
**未确认**：`rTone` / `rIntonation` 在 SV2 UI 上对应哪一项（数值域也没测，**别乱写大值** —— 量级失控的音高参数曾让宿主闪退，见 `tools/known-bugs.json` 的 `SV-002`）。

> 🛠 **已工具化**：MCP 工具 **`sv_mark_mandarin_tones`** —— 上面三步一条命令走完：
> 读整组（桥 op `get_lyrics_attrs`）→ 按词查声调（`pinyin-pro`；**歌词自带调号 / `ni3` 式数字时直接读**，不查词典）→
> **默认 dry-run** 出方案（`apply: true` 才写 `set_note_rap_accents` 并逐音符回读）。参数 `onlyRap`（默认 true）只标 `musicalType` 为 rap 的音符；
> 非中文歌词自动跳过。实现见 `server/src/lyric/tone.ts`。

**纪律**：① **不改歌词、不改语言**（§5.2 与 `akdagent-playbook` §0.6b）；② 只标**中文**音符（rap accent 本身就是普通话专属）；
③ 标完回报**改了哪些音符（索引 + 字 + 声调）**，让用户能核对；④ 多音字**拿不准就问用户**，别硬猜。

### 5.4 读回"宿主到底怎么算的"（写词校验用）

- 工具 **`sv_get_computed_attributes`**（SV2 2.1.1+）一次拿到每个音符的
  `accent`（计算出的重音）、`rapTone` / `rapIntonation`（说唱语调）、`phonemes[]{symbol,language,...}`（**实际生效语种**）。
  这是"我在她嘴里听起来对不对"的**最近似代理**：语种错了、音素缺失、重音与预期不符，一眼能看出来。
- 音高线（谁在哪个音上滑）用 **`sv_get_computed_pitch`**；两工具都会**自动轮询**等宿主算完。
- ⚠️ **读到全空时，先查两条前置，不要先怀疑"渲染太慢"**（详见 `sv-project-format` 技能 SKILL.md 的 §B / §A）：
  1. 该音符组是否**经 NoteGroupReference 挂在轨道上**、引用窗口是否**覆盖了内容**（SV2 **没有**"自动存在的主组"）；
  2. **词的语种与声库是否兼容** —— 例：英文声库 + 中文词 ⇒ **无音素 ⇒ 根本不渲染**。
- **SV1 vs SV2**：`getComputed*` 系列 **SV1 没有**（2.1.1+）；
  那 12 个音高参数（`tF0Offset` / `tF0Left` / `tF0Right` / `dF0Left` / `dF0Right` / `tF0VbrStart` / `tF0VbrLeft` / `tF0VbrRight` / `dF0Vbr` / `pF0Vbr` / `fF0Vbr` / `tNoteOffset`）
  **只在 SV1 存在**，**SV2 一个都没有**，且 `setAttributes()` 不校验 —— 写不存在的字段**不报错、静默忽略**。
  ⇒ **凡写属性必回读**。

### 5.5 写谱时的两条实用建议

- **一字一音符**：快段别把两个字塞进一个音符（`sv_apply_lyrics` 会截断多余字符，写出来是"少字"而不是"快"）。
- ⚠️ **短音符的辅音会"吃掉"前一个音符**（rap 快段高发：字号小、时值短 ⇒ 起首辅音被排到 onset 之前，前一个字被截短/含糊）。
  成因、**SV1 / SV2 分开的修法**与待验证项见 **`skills/sv-project-format/SKILL.md`** 的「短音符的辅音吃掉前一个音符」节；
  写词这一侧的对策：**关键句别排得太密**，必要时给辅音重的字（`zh/ch/sh`、带塞音声母）留更长时值。
- **韵脚给长音**：句尾韵脚留 1 拍以上，既让听众听清韵，也给下一句留气口。
- 停顿用 **`-`**（对位工具约定：`-` = 停顿/留空），**别用空格或标点凑**。

## §6 中英混说

- **以句为界切语种**：同一句里中英混排最容易糊（英文连读需要时间，中文一字一音不给时间）。
- 英文部分按**音节**数格子（不是按单词），并在 SV 里检查连读是否被拉长；
- 中文部分的**声调压平**问题在混说里更明显 ⇒ 中文句子优先短句。
- 语体一致（`语体与国风.md` §1-3）：不要一句书面古语、一句街头俚语。

## §7 交稿前检查清单

1. 每小节的**字数**数得出来吗？（对着音符数，不是对着字数统计）
2. **韵脚**落在拍上了吗？重要段落有没有压正拍？
3. 密度**有变化**吗（稀→密→拉宽）？还是一整段一样密？
4. 句子之间有**气口**吗（是否存在连续 2 小节无空拍）？
5. **换 flow** 的位置有没有预兆？副歌有没有跟 verse 拉开？
6. 快段有没有**同音歧义**字（声调压平后被听成别的字）？
7. **punchline 是不是只有一句**？
8. 快段有没有生僻字/拗口声母（`咬字与倒字.md` §3-4）？
9. 中英混说是否**以句为界**？
10. 若用 SV：`musicalType` 设成 `rap` 了吗？`rapAccent` 是否符合段落气质（1 平 → 5 冲）？用 `sv_get_computed_attributes` **读回**核对过吗？
    （**"用户觉得 rap 声调不准"**⇒ 走 **§5.3 自动标记声调**：按词查声调 → 逐音符标记 → 回读）

## §8 常见毛病与改法

| 症状 | 病根 | 改法 |
|---|---|---|
| **像念课文** | flow 全是正拍、密度均匀、韵脚不看拍 | 先排格子（§3），加入切分与拉伸；韵脚压正拍 |
| **听不清词** | 语速快 + 声调压平 + 生僻字 | 换常用字；歧义句放慢或加气口；关键句给长音 |
| **没劲、平** | 没有"起—压—炸"，全程一个密度 | 前浅后密再拉宽；punchline 只留一句 |
| **上不来气** | 完全没有空拍 | 句间至少留半拍到一拍 |
| **副歌不炸** | hook 跟 verse 密度一样 | hook 拉宽、句子变短、重复 |
| **越听越乱** | 一段里换了三次 flow 且无预兆 | 一段一个主型，最多一次变化，变化前压正拍 |
| **唱出来像另一个人写的** | 中英混排/语体跳档 | 以句为界切语种；整篇语体维持同一比例 |
| **SV 里参数写了没反应** | 属性写了但不回读 / SV2 根本没这字段 | 回读验证；SV2 用曲线而非 12 音高参数 |
