# 借风格护栏（"像某某"的处理）

> 补充 `SKILL.md` §12。核心：**能借的只有手艺** —— 听感可以像，素材不能像。
> 📌 来源：`SJY051/music-composition`（文档 CC BY 4.0 / 代码 MIT）的**思路**启发，**文字为自行撰写**、未逐字复制。
> 案例：`../examples/借鉴变成照搬.md`（"先分清哪些能借"对照表 + 五步具体动作）。

## 1. 把"像某首歌 / 某歌手"翻译成手艺变量

用户说"像 X"，**能借的只有手艺**。翻译成九个变量：**速度区间 · 律动类型 · 和声密度 · 曲式 · 音域与咬字方式 · 配器密度 · 编曲层次 · 能量曲线 · 制作年代感**。

- 这些变量在本 skill 里各有落点：律动 → `律动与鼓组.md`；和声密度 → `和声进行.md`；曲式 → `段落结构.md`；配器密度与层次 → `编曲配器.md`、`混音与母带.md`（空间预算）；能量曲线 → SKILL §6 情绪打分。
- **不碰**：旋律 · 歌词 · 标志性 riff · 采样 · 制作人签名音 · 极具体的嗓音身份 · 某张唱片里可辨识的编曲序列。

## 2. 传统 / 地域音乐：点名，不要笼统标签

要具体到：**哪个传统 / 哪个地域 / 什么语言 / 什么功能（仪式 · 舞曲 · 叙事）/ 什么节奏体系 / 什么乐器惯用 / 什么表演场合**。

**不要**用"异域风味 / 东方色彩 / 亚洲感"这类**笼统标签** —— 它们几乎没给信息，还容易失礼。

## 3. 时效性：潮流、榜单、平台规范一律当"研究任务"

静态文档只写**稳定的手艺惯例**；**曲风潮流 / 榜单 / 平台规范 / 参考艺人 / 版权政策**都会过期 ⇒ 用到就**现查现核**；若写进文档，标上"快照日期"，别把快照当现状。

## 4. 已剔除、不要补回的两类内容

- **已剔除，不要补回**：把规格表**编译成 Suno / YuE2 之类生成模型的提示词**这类具体后端流程 —— 宿主是 **Synthesizer V / Instrument X**，与我们无关；**只保留"规格表"这个抽象概念**（见 `规格表.md`）。
- **已剔除，不要补回**：把"编曲"直接落成具体 **DAW 工程模板**的做法 —— 走 `sv_write_chords` / `sv_generate_melody` 落音符，不做 DAW 模板。
