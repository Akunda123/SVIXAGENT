# 主旋律生成（Melody Writing）

> 补充 `SKILL.md` §3.1。主文件只留最硬的三条（自己唱一遍 · 中文 6-7 字 · 别通篇 `do-mi-so`），**展开、判据与工具链路都在本文**。
> 建议读法：§1 三证据（一段旋律有没有结构）→ §2 方向性 → §3 挂留思维（最立竿见影）→ §6 喂工具；**§7 是复核清单（只有用户点名要看/要修某段旋律时才走）** → §9 怎么给算法下指令。

## 0. 先分清两条路：人写 vs 工具生成

| 路 | 谁在做 | 什么时候用 | 纪律 |
|---|---|---|---|
| **人写旋律** | 用户给动机/情绪，我们给判据与诊断 | 用户自己有想法、或要我评一段旋律 | 创作主体是人 —— 表达什么、什么情绪，**回来问用户**（`SKILL.md` §0）|
| **工具生成** | `sv_generate_melody`（本地**结构引擎 v2**，不占桥）| 用户要"给我一版草稿"、要往工程里铺 MIDI | 它是**草稿机、不是作曲**；生成后**不自动体检** —— 用户要求复核时才走 §7 |

> ⚠️ 作词 · 作曲（生成旋律）· 编曲 · 自动配和弦 —— 都属"**替你创作**"，**动手前先问用户**（见 `akdagent-playbook` 技能）。**低置信就不改**。

## 1. 三个结构证据：一段旋律"有没有结构"就看这三条

> 📌 来源：`SynthVCopilot/SKILLS`（composition-arrangement）「旋律的写法」（摘要改写）

把一段旋律（自己哼的、或工具生成的）逐条过一遍：

| # | 证据 | 怎么查 | 中了会怎样 |
|---|---|---|---|
| 1 | **全落在五声音阶上** | 把用到的音级列出来，看是不是只有 do-re-mi-so-la（宫商角徵羽）| 没有色彩张力：古风可以，现代流行会"平"（见 §4.2）|
| 2 | **没有句法结构** | 能不能分出前句/后句、问句/答句（4+4 或 2+2）| 是一串音，不是一段旋律 |
| 3 | **一句跨了八度** | 数这一句最高音到最低音的距离 | 唱不了、没气口，人声尤其致命 |

**三条全中 = 典型"没有结构的旋律"**：本质是音高随机游走。修的顺序是先给句子（§2），再给颜色（§3）。

另有一条硬约束：**中文一句 6-7 字，留 1-2 秒气口**（`SKILL.md` §3.1）。字多到唱不完，跟旋律本身写得好不好无关。

## 2. 方向性：级进与跳进的分工

> 📌 来源：同上（摘要改写）

- **级进（二度）走"线条"**：负责连接，负责"唱得下去"。
- **跳进（三度以上）给"重点"**：一次跳进就是一次强调 —— 跳进多了等于没有重点。
- **上行之后要有回走**：旋律是弧线不是直线。一路往上顶，累，而且到副歌就没地方去了。
- **高点只放一次**，放在整段/整首的 **2/3 附近**，前后都要有铺垫与回收。
- **落音挑情绪**：要安定收 do/mi/sol，要不安收 la/ti/fa（`SKILL.md` §3.1）。
- **判断动作**：把音高走向画出来（脑内也行）。若是一条平直的线、或单调上升的线 —— 方向性这一关没过。

## 3. 挂留和弦思维写旋律（最立竿见影的一招）

> 📌 来源：同上（摘要改写）

同一个和弦里可选的音有好几个。**通篇 `do-mi-so` = 全是和弦内音 = 听着像儿歌。**

换成下面这些带挂留/延迟解决的走向，颜色立刻就变了：

| 走向 | 音的关系 | 听感 |
|---|---|---|
| `do-re-so` | 2 音挂留 → 落到 5 | 有期待感，最常用 |
| `do-so-re` | 先 5 后 2（逆序）| 更"绕"，现代流行味 |
| `do-la` | 用 6 音代替 5 | 一点忧伤色彩 |
| `do-si-so` | 导音下行 | 收束感强，适合句尾 |

**为什么有效**：音仍在和弦体系内（不违规），但**落点与经过音换了** —— 等于不换和弦也换了色彩。

> ⚠️ 必须与避免音铁律一起用：旋律音要么**压在**和弦内音下方（低小二度无妨），要么**高出去大二度以上**；**高小二度是硬伤**（`SKILL.md` §3.2 · `examples/旋律与和弦打架.md`）。

## 4. 三条常见"旋律病"

### 4.1 循环不留起伏

循环若写成 `do-si-do-la-do` 这类，本质等于和声上一路 4536251 —— **一直在原地打转**。循环里必须留一次上行、或一次真正的落定，否则听众听不出段落推进（呼应 `references/段落结构.md` §3）。

### 4.2 五声音阶滥用

五声是国风的基本盘，但**整首全五声 + 一句一转**会写成《茉莉花》。要现代流行味，就得在关键处放进 4 音/7 音（清角/变宫）制造张力。

### 4.3 吐字密度与风格不匹配

| 密度 | 典型 | 要点 |
|---|---|---|
| **密**（一字一音、少拖长）| Ed Sheeran 式的叙事推进 | 字多但字调要跟着走向走（`sv-lyricist` 的倒字避让）|
| **稀**（大量长音、拖腔）| K-pop / 抒情向 | 长音要落在能站住的和弦音上 |
| **K-pop 专项** | 重在律动 | 旋律可以密，但**不许破坏律动** —— 音压在律动上（落点见 `references/律动与鼓组.md`）|

## 5. 主题与素材：动笔前先定

> 📌 来源：`SynthVCopilot/SKILLS`（摘要改写）

- **主题要早出现**：前 8-16 小节里必须让人听到"这首歌的主题"，否则后面全在补。
- **先定和声节奏，再按 4/5/6 个和弦分组**：一小节一个还是两个先定死，旋律的句法跟着分组走。
- **拿节奏当主题时，必须同时给出明确的旋律走向** —— 只有节奏、没有走向，等于没有主题。

## 6. 把旋律落进 AKDAgent（工具链路）

**参数速查**（`sv_generate_melody`，纯本地、不需宿主在线）：

| 参数 | 取值 | 注意 |
|---|---|---|
| `key` | `C` / `Am` / `F major` | 写明了大小调就按 key（`Am` ⇒ 小调）；只给主音（`C`）时由 mood 定大小调 |
| `chordProgression` | `['C','G','Am','F']` | 不填则默认 I-V-vi-IV；**逐小节循环**（一小节一个） |
| `mood` | bright / happy / sad / dark / tense / calm / epic | 情绪维度（决定节奏细胞/能量/落音），**不含风格维度** |
| `bpm` / `barCount` | 数字 | 变速段落要另行处理（`sv_apply_tempo`）|
| `phraseBars` | 数字（默认 4）| 一句几小节 —— 决定**分句与气口**位置 |
| `highPointBar` | 数字（默认 ⌈小节数×2/3⌉）| 旋律高点落在第几小节（1 起）|
| `breathBeats` | 数字（默认按情绪 0.5~1.0）| 句末气口拍数 |
| `useArpeggio` | true / false | 顺带铺一层琶音伴奏（低八度，跟和弦音走）|
| `seed` | 数字 | 要复现同一版就固定 seed |
| `outPath` | `.mid` 路径 | 给 IX 乐器用时写文件 |

**引擎做了什么**（回执里的 `plan` 就是它的结构说明，可直接讲给用户听）：

| 结构 | 做法 |
|---|---|
| **主题发展** | 动机按句法角色走 `A → A'（模进）→ B（对比/倒影）→ A''（回归+扩张）`，不再逐小节重新随机 |
| **句法 + 气口** | 按 `phraseBars` 分句；句末固定留气口（抒情类情绪句内还多留一拍） |
| **终止落音** | 末句落**主音**（完全终止），其余句落属音/三音/六音（半终止） |
| **单一高点** | 高点默认落在 2/3 处，且全曲只出现一次（其余小节音级上限被压到峰值-1） |
| **和弦对齐** | 强拍踩和弦内音；弱拍留经过音/挂留音做色彩 |
| **避免音护栏** | 生成时就把"高小二度"压掉（降到和弦内音），不让硬伤进工程 |
| **句内音域** | 一句之内不超过八度（保证唱得动、留得下气口） |
| **时值收口** | 一个音的时值不越过下一个音的起点、不越小节线（`A''` 句会把时值 ×1.5，这里必须兜住，否则 **0.75 拍的音塞进 0.5 拍的格子 ⇒ 重叠**；实测踩过 15 处）|
| **力度** | 强拍重、弱拍轻（`vel` 可直接落 SV dynamics；< 0.5 是伴奏层） |

**扒带 → 生成的闭环**（缺这一环，key / chordProgression 就只能瞎填）：

```
sv_analyze_audio（BPM / 调性）
  → sv_analyze_chord（逐段和弦）
  → 归纳 key + chordProgression
  → sv_generate_melody（固定 seed，出 2-3 版挑一版）
  → sv_write_chords（把和弦铺进工程）
  → sv_apply_lyrics（填词对位）
```

> `sv_check_melody`（§7）**不在上面这条链里** —— 它不进生成流程。它是**独立的复核工具**：等你或用户指着一段**已经写好的旋律**说"看看这段"时才跑。

- 扒和弦的顺序、以及"找调用 7→1 测归属感"，见 `references/和声进行.md` 的扒和弦与找调一节。
- 生成结果是**参考级草稿**：key / BPM / 和弦对得上就能用；**旋律线条必须人过一遍**（§1 + §2 + §8）。
- 伴奏怎么铺开不在这里 —— 见 `sv-texture` 技能；填词对位见 `sv-lyricist` 技能（词格 / 倒字）。

**写进工程的纪律**：生成的旋律要落到**新建的独立组**里（如 `AKDAgent Melody`；建组时打 `akdagentTemp` 标记，日后可一键清理）—— **SV2 主组不可编辑**，桥侧对"写主组"有守卫，而 **`run_script` 是裸逃生口、不豁免这条**（写音符的配方与两条 API 实坑见 `akdagent-playbook` 技能）。

**边界说明**：把**已经写好的**旋律唱好（重音判断 / 倚音 / 音高线 PitchControlCurve）是调声的活，不是作曲 —— 走 `sv-scripting` 技能的 `references/07-melody-accent-pitch-params.md`。

## 7. 旋律检查：**给已写好的旋律做复核**（`sv_check_melody`）

> 🔴 **定位：这个检查是用来"修"**已经写好**的旋律的 —— 人工写的、自动生成的、别人给的，都适用；它**不属于生成流程**。
> 🔴 **触发：由用户指出才开始检测** —— 用户说"这段旋律帮我看看 / 有没有问题 / 帮我修一下"（或点着工程里某一段问）时才跑。**不要**在新生成一版之后自作主张地顺手跑，也不要拿它当生成器的验收门。

上面 §1-§5 是**判断**，这一节是**把判断变成可跑的检查**。用法二选一：不传 `notes` ⇒ 读 **SV 当前组**的旋律（工程里已有的那一段）；传 `notes`（`pitch` + `startBeat`/`durBeats`）⇒ 直接校验手头这份。`key` 省略则用 Krumhansl 自动推断；给了 `chordProgression` 才查和弦相关判据。

> 🔴 **只出清单，绝不自动改**：检查只产出一份建议清单 —— 改不改、改哪条，由用户定。用户点头后才动手，且**一次只改一处**（好判断是哪个改动起了作用，见 `references/规格表.md` 的 A/B 用法）。

### 交付形态：**列清单 → 用户自选 → 再说细节**

> ❌ **不要逐项确认**（不要"这条要改吗？"一条条问，不要拿它去弹面板提问）。
> ✅ **正确姿势**：把检查结果**一条一条列出来**，让用户**自己挑**要动的地方；用户点到哪条，我们**才**说那条的细节与改法。

**清单怎么写**（每条一行，够用户挑就行）：

```
N. [严重度] 判据 · 位置 · 现象 · 一句改法方向
```

- **必须带位置**（第几小节 / 第几拍 / 哪个字 / 哪个音），否则用户没法挑；
- **一句改法方向**写清"往哪改"，**不写完整方案**（方案等用户点到了再说）；
- 按严重度排（error → warn → info），**别把 20 条 info 混在 3 条 warn 里**；
- 检查回执里的 `issue.id` / `where` / `message` 已经够用，**照抄转述即可，不用另造格式**。

**用户点选之后**才做的事：说清**这一条的细节**（为什么是问题、改它会牵动什么）+ **具体改法**（几个候选、各自代价）→ 用户拍板 → **一次只改一处** → 改完回读回报。

### 主要检查（用户点名的四条，先看这四条）

| # | 检查 | issue id | 判据（机器怎么算）| 怎么改（供用户挑）|
|---|---|---|---|---|
| 1 | **不留气口** | `breath` | 按 `phraseBars` 分句后，句末到下一句之间 < 0.5 拍 | 句末音提前收（留 0.5-1 拍）；抒情类留够 1 拍 |
| 2 | **六度以上大跳** | `leap` | 相邻音音程 **≥ 9 半音**（大六度及以上）| 大跳之后**反向级进**走回来；或拆成"跳进 + 经过音"两级；真想要这个高点就保留（好坏由人定）|
| 3 | **单一音重复（在一个音上打转）** | `repeat` · `monotone` | ① 连续同音 ≥3 次；② 某个音占了整段 ≥1/3（且 ≥4 次）| 换相邻音级走动；或把重复的几个并成一个长音 |
| 4 | **大段短音符（吐字不清）** | `short-run` | 连续 ≥6 个 ≤0.5 拍（八分及更短）的音 | 留一个长音或气口；把其中几个字拉长；或整句降密度 |

### 其余判据（按需看）

| 判据 | issue id | 严重度 | 怎么改 |
|---|---|---|---|
| 避免音（旋律音比和弦内音高小二度）| `avoid-note` | **error** | 把那音降半音，或换和弦把它收进去 |
| **音符重叠**（单声部旋律不许叠）| `overlap` | **error** | 把前一个音的时值收到下一个音的起点（与桥侧 `sv_get_layout` 同口径）|
| 调内音比例 < 85% | `scale-fit` | warn | 查是不是调式/和弦进行与 key 打架（小调 key 别配大调进行）|
| 一句跨八度 | `octave-leap` | warn | 把那句的极值音换八度（同音名）|
| 高点不唯一（多个小节到最高音）| `highpoint-not-unique` | warn | 只留一个高点，其余降下来 |
| 强拍和弦内音 < 60% | `chord-weak` | warn | 强拍换和弦内音，色彩音挪到弱拍 |
| 全落五声音阶 | `pentatonic-only` | info | 古风可用；要现代味就在关键处放 4/7 音 |
| 通篇和弦内音（≥95%）| `too-chordy` | info | 加挂留/经过音（§3）|
| 高点不在 45%-92% 之间 | `highpoint-position` | info | 挪到 2/3 附近 |
| 连续上行后没回走 | `no-return` | info | 高点后安排回落 |
| 每句音符数完全一样 | `flat-density` | info | 用 `phraseBars` / 段落设计做密度曲线 |
| 末句不落主音 / 中句落音随意 | `cadence-final` · `cadence-mid` | info | 末句落主音，中句落属/三/六音 |
| key 只给了主音，调式按实测取小调 | `mode-assumed` | info | 想让调式确定，就在 key 里写明（`Cm` / `C major`）|

### 和弦冲突：**慎用**

`avoid-note`（以及 `chord-weak` / `too-chordy`）**都依赖 `chordProgression`**。给之前先想清楚和弦是从哪来的：

- 用户**自己定的**和弦 ⇒ 可以按硬伤处理（`avoid-note` = error）；
- 我们**扒出来的**（`sv_analyze_chord`）⇒ **只作参考、慎用** —— **扒和弦不一定准**，错一个和弦就会凭空多出"硬伤"；这种情况把结论当提示看，或者干脆先不查这条；
- 和弦里有**调外音**（例如 Am 调里用 E 大三和弦，含 G#）时，避免音判据会跟本调音阶打架 —— **报出来是对的，要不要听它的由人定**。

回执里还给**可用数字**：`metrics.scaleFit` · `pentatonicFit` · `chordToneOnStrong` · `phraseSpans` · `breathGaps` · `notesPerPhrase` · `maxLeap` · `shortestNote` · `shortRunCount`，以及 `verdict.text`（`X 处硬伤 · Y 处警告 · Z 条提示`）与 `verdict.advice`（建议清单，写明"只列不改"）。**只有 error 必须处理**；warn / info 逐条判断。

## 8. 旋律专项自查（交付前跑一遍）

> 这一节是**人耳自查**，谁都能随时做。**机器检查（§7）不在这里自动触发** —— 只有**用户要求复核**那段旋律时才跑。

1. 自己**从头唱到尾**：哪一句没气了？哪个字唱不出来？
2. 三证据（§1）：全五声？有句法？跨八度？
3. 方向性（§2）：有没有一次真正的上行、之后是否回走？高点是不是只有一个？
4. 色彩（§3）：有没有 2-3 处用了挂留/延迟解决，而不是通篇 `do-mi-so`？
5. 避免音（`SKILL.md` §3.2）：**逐音查高潮/重音处有没有高小二度** —— 5 分钟能查完。
6. 词曲咬合：字调跟走向是否拧着（倒字）；中文是否 6-7 字一句。
7. 与伴奏的关系：旋律重音是否落在鼓的重音上？有没有跟低音撞同度（`references/律动与鼓组.md`）？
8. 用生成工具时：**seed 记下来了吗**？人工改了哪几处，能不能说出来？

## 9. 怎么给算法下指令（LLM / 助手契约）

这一节解决"**本地乐理算法死板**"这件事的正确分工 —— **LLM 决定"说什么"，算法决定"怎么说、合不合法"**。

**三条立即可用的路**（按推荐顺序）：

1. **参数 + 局部改写（现在就能用）**：调参重生成，或按用户的话局部改一个音 ——
   - "第 5 小节的高点降三度" ⇒ 调 `highPointBar` 或直接改那一个音；
   - "全五声太寡淡" ⇒ 在关键处放 4/7 音（§4.2）；
   - "句末没气口" ⇒ 调 `breathBeats` 重生成，或把末音时值收短。
   **一次只改一个字段/一处**，才说得清是哪个改动起了作用（对照 `references/规格表.md` 的 A/B 用法）。
2. **多候选 + 挑一版**：同一个 `key/mood/chordProgression` 换 2-3 个 `seed` 各出一版，挑方向对的那版 —— **别在第一版上反复磨**，容易越磨越平。
   （**若用户要求复核**，再拿 §7 的清单在这几版之间比 issue —— 但这仍然是"用户点了才做"。）
3. **直给音符（自由度最高，风险也最高）**：让 LLM 出**音级 + 时值**（`[{deg, oct, beat, dur}]`），由算法/我们负责量化到网格、吸附调内音、修避免音、夹音域、补气口、修落音 —— **不要直接让 LLM 吐 MIDI 音高号**：它给"关系"强、给"绝对数字"弱，而且数字没法一眼校验。

**边界（不许越线）**：
- 生成类都属"**替你创作**" —— 动手前先问用户；情绪/表达回来问用户（§0）。
- **检查类由用户指出才做**（§7）：不主动跑、不当生成器的验收门、不拿清单去改用户没提的地方。
- 拿不准就不改：**低置信的判据当 info 看**，别为了"过检查"把用户的想法改没了。
- `seed` 与改动清单要留痕（§8 第 8 条），否则下次没人能复现这一版。
- 借风格只借手艺：旋律这条是硬红线（`references/借风格护栏.md`）。
