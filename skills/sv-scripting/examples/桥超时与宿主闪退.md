# 案例：桥超时 / 宿主闪退 —— 读 automation 点数据踩雷 + 别忘重载桥

> 分类：桥/宿主故障 ｜ 症状：工具超时 10s、宿主直接重启、或工具报 "unknown op"

## 问题 A（⚠️ 2026-09-20 更正：当时的诊断是错的）：读了 automation 点 → 宿主冻住

想读一个音符组的颤音曲线，写了（**注意：没传参数**）：

```javascript
var auto = group.getParameter("vibratoEnv");
var pts = auto.getPoints();        // ⚠️ 参数个数不对（本 API 要 2 个）
```

桥超时、Instrument X 整个重启，未保存的改动全丢。

**当时的诊断**：「`getPoints/getAllPoints/getLinear` 返回的是宿主内部对象、桥没法把它序列化回客户端」，并据此把好几个 API 都标成了"危险"。
**🔴 2026-09-20 在 IX 1.0.1 上重测，这个诊断被直接证据否掉了**：

- `getAllPoints()`（**0 参**）返回的是**普通嵌套数字数组** `{{位置,值},…}`（实测 `{{0,-800},{1411200000,0},{2822400000,800}}`），
  **原样 `return` 给桥序列化，319ms 正常**；`getDefinition().range` 同样（`[-800,800]`，252ms）⇒ **序列化从来不是问题**。
- **真正的坑是参数个数**：`getPoints(start, end)` 要 **2 个** · `getLinear(blick)` 要 **1 个** · `getAllPoints()` 要 **0 个**。
  写错只抛 `InvocationError`（消息里写明「预期 N 个参数」），**不再冻桥**。
- ⇒ 1.0.0 那次冻桥，最可能是**参数不对 ⇒ 宿主弹模态框 ⇒ 挡住 Lua 主线程**（与 `SV-001` 记的弹框冻桥同机制）；
  **1.0.1 改成抛错**。

**现在只保留一道防线 = 版本检测**：桥在 `ping`/心跳/boot 里报 **`hostOutdated`**，
**检测到 IX 1.0.0 就先让用户升级宿主（≥1.0.1）**，再做读点类操作。完整证据与复检方案见 `known-bugs` 的 **IX-001**。
**教训（比结论本身更有用）**：当时 `pcall` 把它当"序列化卡死"下了结论，其实是**参数个数** —— 错误消息里就写着原因，
**别把 pcall 的失败当成"接口坏了"，先把错误原文读出来**。

## 怎么改 A

- **读自动化点**：宿主内**直接调** `getAllPoints()`（0 参）/ `getPoints(start, end)`（2 参）即可（IX ≥1.0.1，返回普通数组）；
  想读**没保存**的工程、或做批量分析，走磁盘 `.ixp`/`.svp` JSON → `library[].parameters.<type>.points`
  （扁平交替数组 `[x0,y0,x1,y1,…]`，用 `i%2` 取，**不要** `Object.keys(point)`）。
- 宿主内安全读写：`get(x)` / `add(x,y)` / `removeAll()`。

```javascript
var auto = group.getParameter("vibratoEnv");
auto.removeAll();                 // ✅ 安全
auto.add(0, 1.0);                 // ✅ 安全
var v = auto.get(0);              // ✅ 安全（0 → 1.0）
```

## 问题 B：改了桥脚本，工具报 "unknown op"

给桥加了新 op（如 `write_chords`），MCP 侧调用报：

```
{"ok":false,"error":"unknown op: write_chords"}
```

## 诊断 B

**桥脚本是宿主内的常驻脚本，改了源文件不会自动生效**。当前会话跑的还是**加载时的旧版**。

## 怎么改 B

```powershell
# 1. 把源同步到各宿主的 scripts 目录（现役是 Lua 桥；或直接跑仓库里的 sv\install.ps1）
Copy-Item sv\lua\AKDAgentBridge.lua "$env:APPDATA\Dreamtonics\Instrument X\scripts\Agent\AKDAgentBridge.lua" -Force
Copy-Item sv\lua\AKDAgentBridge.lua "$env:APPDATA\Dreamtonics\Synthesizer V Studio 2\scripts\Agent\AKDAgentBridge.lua" -Force
Copy-Item sv\lua\AKDAgentBridge.lua "C:\Users\<u>\Documents\Dreamtonics\Synthesizer V Studio\scripts\Agent\AKDAgentBridge.lua" -Force
```
2. 在宿主里**重新运行** `Agent → AKDAgentBridge`。⚠️ Lua 桥一旦在跑，再点一次"运行"**不会**替换旧实例 ⇒ 先调 `stop` op（或重启宿主）再重跑。
3. MCP 侧改了 `tools.ts` 要**重编译 dist 并重启 MCP**（它是独立进程 `node dist/index.js`）。

> **验证桥版本**（现役做法，不靠记忆）：看心跳 `akdagent-hb-<host>.json` 的 `bridge` 字段（当前 **1.0.0**），或直接 `sv_ping` / 看 `akdagent-boot-<host>.json`。🆕 同一批载荷里还带 **`hostOutdated` / `hostWarning`**（版本检测：宿主过旧时提示升级）。
> ⛔ 旧做法是"让桥返回 `typeof svhChordSegsToNotes`"—— 那是 **JS 剪贴板桥时代**（已退役，`svh*` 函数名不存在了）。

## 可复用判断标准

1. **"超时 + 宿主冻住/重启" 先看两处**：① **错误原文**（`pcall` 的失败值里有「预期 N 个参数」这类线索，别跳过它下结论）② **宿主版本**（IX 1.0.0 有已知冻桥问题：读点类 API 会弹框挡 Lua 线程 ⇒ 桥会报 `hostOutdated`，先让用户升级）。**别一上来就归因成"宿主内部对象没法序列化"** —— 2026-09-20 实测那条不成立。
2. **"unknown op" = 桥是旧版**，同步文件 + 在宿主里重跑桥。改 MCP 工具则要重编译 + 重启 MCP。
3. 写操作前 `proj.newUndoRecord()`（无参数！）——宿主闪退时至少能救回一部分。
4. **验证版本**不要靠记忆，用"探测只有新版才有的符号"来确认。
5. 宿主闪退会丢未保存改动 → 关键节点及时 Ctrl+S，或从 recovery 目录恢复。
