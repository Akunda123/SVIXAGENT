# 案例：纯音频工程里 getMeasureMarkAt() 全部返回 positionBlick=0

> 分类：宿主 API ｜ 症状：按小节对齐的工具算出错误偏移（对齐到第 1 小节，而不是指定小节）

## 问题

在 Instrument X 里打开一个**只有音频轨、没有音符组**的工程，调用 `sv_align_audio`（`anchor:'measure', measure:5`）想把音频第一拍对齐到**第 5 小节**。

结果 `align_audio` 报错/对齐不对。逐个探测发现：

```javascript
ta.getMeasureMarkAt(1) → { position:0, positionBlick:0, numerator:4, denominator:4 }
ta.getMeasureMarkAt(2) → { position:0, positionBlick:0, numerator:4, denominator:4 }
ta.getMeasureMarkAt(3) → { position:0, positionBlick:0, numerator:4, denominator:4 }
……
ta.getMeasureMarkAt(6) → { position:0, positionBlick:0, numerator:4, denominator:4 }
```

**每个小节的 `positionBlick` 都是 0** —— 小节位置无法从 API 拿到。

## 诊断

这是**纯音频工程（无音符组）下的宿主行为差异**：小节标记没有被实体化，`getMeasureMarkAt(m)` 对任何 m 都返回占位对象。
它能读出 `numerator/denominator`（拍号 4/4 是对的），但**位置字段全是 0**。

> 注意：`getTempoMarkAt(0)` 是**正常的**，返回 `{bpm:120, position:0, positionSeconds:0}`。
> 所以"tempo 能读、小节读不到"这个组合，不是工程坏了，是 measure mark 没实体化。

## 怎么改

**不要依赖 `getMeasureMarkAt` 定位小节**。用 **tempo + 拍号自己算**：

```javascript
// 第 N 小节起点 blick（4/4、120BPM 下）= (N-1) × 4 拍 × SV.QUARTER
// 用工程换算是 getBlickFromSeconds，避免手算 bpm
var measureStartBlick = timeAxis.getBlickFromSeconds((measure - 1) * beatsPerBar * (60 / bpm));
```

验证：120 BPM、4/4 下
- `getBlickFromSeconds(8)` = `11289600000` blick = 16 拍 = **第 5 小节起点** ✅
- 与 `(5-1) × 4 × 705600000 = 11289600000` 一致。

## 改后效果

- 不再依赖失效的 `getMeasureMarkAt`，用 tempo/拍号换算得到正确的小节起点。
- 音频轨按 `setTimeRange(absoluteOnset, duration)` 设绝对起点（offset 恒 0），对齐正确。

## 可复用判断标准

1. **`getMeasureMarkAt` 只在有音符内容的工程里可信**；纯音频工程里要**校验它返回的位置是否为 0**。
2. 小节位置可以**从 tempo + 拍号推导**（不依赖 measure mark）：`(N-1) × 每小节拍数 × 每拍 blick`。
3. 探测 API 时**先看值是否合理**（全 0 就是失效），不要拿到对象就当有效。
4. 音频轨位置**统一用绝对 onset 表达**（`setTimeRange` / `blickAbsoluteBegin`），不要叠 `setTimeOffset`——
   否则"onset + offset"两处叠加，后续难核算。
