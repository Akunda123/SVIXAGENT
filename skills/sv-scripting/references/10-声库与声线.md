## 1. 两类声库：先把总表钉住

### 1.1 对照表

| | **采样声库**（Standard 标准版） | **AI 声库** |
|:--|:--|:--|
| **底层做法** | 歌手按不同音高、不同发音分别录音；编辑器把录音**切片、挑选、拼接**成歌声 | 用一批真人演唱数据训练模型，让模型**学会「这个人怎么唱」**，再按谱子重新生成 |
| **强项** | 能唱的音域更宽，手动干预余地大，每一处细节都握在自己手里 | 出声接近真人，不太会崩，上手门槛低 |
| **独有的东西** | **采样音阶**（同一个字按演绎强度分成几档录法）＋ **备用采样**（界面里的 `DFLT`，用来换音色/补不足的音） | **音区偏移**（等于模拟换采样）、**音素力度**、**多声线**、以及 `cl`（气泡音素材） |
| **你额外要学的** | 什么场合换哪个采样音阶、什么时候切 `DFLT` | 音区偏移怎么用（→ 07 §3.2h）、声线怎么切（→ 本篇 §4） |

### 1.2 哪些手法通用，哪些必须分库处理

| 层面 | 两类库是否同一套手法 |
|---|---|
| 音高线（Pit）、颤音 / 转音 / 滑音 | ✅ 通用 |
| 重音判断、音头与音尾的手势 | ✅ 通用 |
| 咬字与音素调整、呼吸音/气口 | ✅ 大体通用 |
| **换采样**（采样音阶、`DFLT`） | ❌ 只有采样库有 |
| **音区偏移** | ❌ 只有 AI 库有（→ 07 §3.2h） |
| 张力 / 响度 / 发声 / 气声的**反馈强度** | ⚠️ 每个库的脾气都不一样，必须在**本库上自己试出来** |

> **一句话结论：绝大部分调校动作是跨库通用的。真正需要分库处理的只有两处 —— 怎么换采样、怎么用音区偏移。**

### 1.3 为什么练手建议先练采样库

采样库把所有决定都摊在明面上：音高、时长、用哪份采样、用哪一档音阶，全都要你自己拍板。
AI 库会替你做掉一部分决定，画得糙一点也听不太出来 —— 省事，但学不到东西。

建议顺序：**先用采样库把 Pit 和参数基本功练扎实（07 / 08）**，再切 AI 库。你会发现 AI 库替你省掉的那部分功夫，迟早要补回来。

## 2. 挑库：判断标准

### 2.1 硬标准 —— 库里得先有你想要的那部分音色

**声库本身的音色里，必须先有和目标气质重合的部分**，剩下那点差别才轮到后期（EQ、性别、音区偏移）去补。
差得太远时，后期是救不回来的：**跨度一大，硬用参数拉，基本一定失真。**

道理很直白：如果任何音色都能靠后期捏出来，厂商何必录那么多个库。

常见翻车：拿甜软稚嫩的声线去唱雄壮民歌，或用沙哑阴郁的库去唱欢快花腔 —— 技术再熟练，味道也是错的。

### 2.2 哪几类风格最挑音色

**民族唱法、美声、戏腔**这三类对音色最挑，不是「有点像不像」的问题，而是整个发声体系对不上：

- **民族 / 戏腔**：讲究特定腔体的集中度与咬字位置，不属于那个体系的库唱出来就是「不像那个剧种」。
- **美声**：对整体发声状态和共鸣的统一度要求最高，技术门槛也最高（练习顺序：先流行后美声）。

这三类遇到不匹配，**换库是唯一解**，不要指望参数。

### 2.3 选版本、选歌本身就是设计

- 同一个歌名，不同歌手的翻唱版本，编曲厚度、律动密度、有没有专门炫技的段落，差别可以很大。**决定调哪个版本，本身就是在做设计** —— 版本自带的难度，后期修不掉。
- 选歌先看**有没有唱法能发挥的位置**。整首歌平铺直叙，最后你会发现无处下笔。

### 2.4 入门选歌四条

| 条件 | 为什么 |
|---|---|
| 词量别太大 | 逐字都要过咬字和音素，量大根本做不完 |
| 中速为主 | 太快来不及画细节；太慢每个音的小毛病都听得清清楚楚 |
| 音域跨度小 | 跨度过大一来音色不统一，二来容易撞上换声点 |
| 优先中文 | 英文一个词常拆成好几个音节、辅音簇又密集，要唱出味道得改的 Pit 量明显更大 |

## 3. 中文声库怎么挑：自己核实，别背表

**故意不放「声库 → 音色 → 音域 → 擅长风格」的完整对照表。** 原因很简单：那种表是别人听感的一次性总结，而声库还在陆续出版本（标准版 / AI 版 / PLUS 版音色并不一样），照抄一张可能已经过期的表，风险比收益大。

要判断某个库合不合适，按下面五步自己过一遍：

1. **先看硬件条件**：这库是采样还是 AI、支持哪些语言、有哪几条声线可用。直接读工程与声库数据（数据目录与工具见**本文 §5**），不要凭印象。
2. **试音域**：写一条从低到高缓慢上行的长音，听它在哪一段开始发闷、从哪一段开始变假。
3. **试音色倾向**：同一句歌词，分别在低、中、高三个区域各唱一遍。明暗、厚薄、集中还是散 —— 这三段的表现就决定了它能唱哪类风格。
4. **试硬边界**：把它往最极端的风格上推（最强张力、最靠上的音区偏移），看它是「变难听」还是「直接散架」。
5. **候选库 A/B**：同一句、同一套参数，两个库各渲染一遍选赢的那个。**别拿不同的句子做比较。**

### 3.1 常见中文库的定位（🔸 全表待核实）

下面这些属于圈内常见说法，**未逐个复核**。🔸 的条目尤其不要当结论用：

| 声库 | 常见定位（🔸 待核实） |
|---|---|
| 赤羽 | 英气偏亮、偏高亢，常见于摇滚 / 古风 / 史诗类 🔸 |
| 诗岸 | 轻柔稚嫩，电子 / 抒情类用得多 🔸 |
| 苍穹 | 成熟稳重、御姐向，抒情 / 古风 / R&B 类 🔸 |
| 海伊 | 俏皮纤细、偏奶气 🔸 |
| 牧心 | 少年感、清爽嘹亮（男声）🔸 |
| 星尘（含 Minus / AI） | 空灵向；标准版与 AI 版取向并不相同 🔸 |

> ⚠️ 上表**只用来建立「音色 ↔ 风格」的判断意识**，不是清单，也不构成选库建议。
> **各库的确切音域、采样音阶的具体音名，一律不写** —— 那属于跟版本绑死的硬数据，请以自己手上装的声库为准（试法见本节五步）。

## 4. AI 库的多声线切换（本篇新增，重点）

AI 声库的一个库里往往带好几条声线（同一个歌手的几种演绎方式）。用得好，一首歌里能做出「前半段轻声、副歌换强声」的层次；用得糙，就会听到明显的接缝。

### 4.1 三条铁律

1. **只在相近的声线之间切。** 落差太大的两条（极柔 vs 极冲）直接对切，一定听得出来。
2. **落差大就找中间人过渡。** 用一条和两边都接近的声线，在**一两个字**上顶一下，再进到目标声线。
3. **切点必须落在「好切」的辅音上。** 落在元音上，两条声线的音色差会被完整暴露。

### 4.2 切点选哪个音素（关键）

| 音素 | 能不能切 | 说明 |
|:--|:--|:--|
| `b` `p`、`d` `t` | ✅ 好切 | 轻辅音，本身自带一个短暂的中断，切点藏在这儿听不出来 |
| `z` `c` `s`（短塞擦音） | ✅ 好切 | 同样有短暂中断可用，是最好用的切点之一 |
| 其他爆发音 | ✅ 一般可用 | 短促，切开后没有拖尾 |
| `m` `n` `l` `r` | ❌ 很难切 | 浊辅音自带音高，切开会听到音高与共振峰的跳变 |
| 拉长的 `s` `sh` `x` | ❌ 很难切 | 连续摩擦音是一条不断的能量带，接缝会完整暴露 |
| 元音（a / e / i / o / u） | ❌ 不要切 | 音色最饱满的位置，落差全露 |

> `s` 出现在两行里并不矛盾：**短促的 `z/c/s` 好切，拉长的 `s/sh/x` 不好切** —— 判断依据是它有多长、有没有持续的噪波。

### 4.3 声线混合 = 现造一条过渡声线

两条声线差得实在太远时，不必二选一：**同时给多条声线非零权重（声线混合），按比例调出一条介于两者之间的音色**，用它来接缝最稳。

用法分两种：

- **整段换色** → 把那一段拆成独立的音符组，在组上挂不同的声线 / 混比配置。
  （"什么时候值得拆、拆了怎么保住连贯"见 **[09-拆轨与拆音.md](09-拆轨与拆音.md)**；这里只讲声线侧。）
- **句内渐变** → 在同一个组里，用 **`vocalMode_<声线名>`** 这条 automation 逐段画（数值 0~150）。它和张力、响度走的是同一套 automation 机制，**注意每条声线各是一条独立曲线，不是一条曲线。**

工程视角（已核对 `api/Automation.md`、`api/NoteGroupReference.md`、`references/06-track-misc.md`）：

- **引用层**：`NoteGroupReference.getVoice().vocalModeParams` → `{ "Soft": {...}, ... }`，每个声线一个对象；
- **automation 层**：`Automation.getDefinition().typeName` 会给出 **`vocalMode_<Name>`**，默认 0、范围 0~150；
- 所以数据上的「混合」= **几条 vocalMode 曲线同时非零**。

⚠️ 两条注意：
① `vocalModeParams` 里各项的文档字段是 `pitch` / `timbre` / `pronunciation`（各 0~150），**未逐项验证具体听感**，🔸 用前先小范围试；
② 名字里的 `pitch` 不是音高参数，别和 `toneShift`、`tension` 混着理解。

### 4.4 实操顺序（建议）

1. 先整段试声线，A/B 听哪条对味；
2. 定好转场位置（乐句交界 / 换气口 / 鼓点），再在那个位置里找「好切」的辅音；
3. 需要过渡就加混比曲线，或插一个属于中间声线的字；
4. 切完**一定整句回听**，重点听接缝前后的响度与亮度是否连得上 —— AI 库自己会做动态，接缝处的电平往往要手动补一点。

## 5. AI 库的坑（逐条 + 应对）

| # | 现象 | 应对 |
|:--|:--|:--|
| 1 | **参数画在画面上的位置，和它实际生效的位置有偏差** | 按耳朵把点前后挪一点；**换声点附近最明显**，要单独试 |
| 2 | **会自己造动态坑**：转音处冒出一个幅度夸张的坑，方向还常和你要的相反 | 手动抹平或反向修掉，别以为是自己的参数画出来的 |
| 3 | **会自己塞气泡音**，而且位置随机 | 不想要就在那个音上处理掉；想要的段落改用 `cl` 明确加 |
| 4 | **低音区 + 快速咬字 → 辅音糊成一坨** | 放慢咬字（拆音 / 加时值）、把辅音抬出来（发声、响度），或整体挪到更舒服的音区 |
| 5 | **`g` / `f` 这类辅音时值不够时会带出基频**，听着像浊辅音 | 把时值补够，或用发声（`voicing`）压下去 |
| 6 | **不认音素 `/U/`**（写上没反应） | 改用 `/o/` 代替。🔸 是否所有 AI 库都如此、新版是否已修，未核实 |
| 7 | **气声与谐波分不干净**，某些频段留残峰 | 要纯净的谐波/气声就走「气音分离导出」再各自处理，别指望参数切得绝对干净 |
| 8 | 张力拉到 0 以下时，AI 不是自然变弱，而是音色变哑 | 见 **07 §3.2e** —— AI 库优先用音区偏移打底，张力只做小幅补充 |
| 9 | **响度画不到绝对零** —— 拉到底频谱里仍能看到残留能量（耳机基本听不出，**可接受**）| 要**彻底**消掉就配合**发声 + 气声**一起切（拆轨切音素时尤其需要，见 **09**）|

### 5.1 呼吸音上的两条坑（两代声库各一条）

| 声库 | 坑 | 对策 |
|---|---|---|
| **采样库** | 呼吸音**本身听着就偏电**（SV 处理采样库呼吸音的方式不够好）| 干脆不在编辑器里加，**改到后期混音时在音轨上贴呼吸音频** |
| **AI 库** | 在**极短空拍**处直接写 `br`，会出难听的气泡音或者卡顿 | 把那个位置**改成 `sil`**，呼吸音**另拆一轨**放进去 |

> ⚠️ 做**带音高的抽气**时，**张力与气声都要拉到底、只留基频**——任何一项留了量，出来的一定是电的。

## 6. AI 库的红利（别只把它当麻烦）

1. **音素切得足够短，AI 会把接缝处的停顿感自动抹掉** → 拆音可以拆得很随意、很生硬，不必担心每个断口都露破绽。这是 AI 库最省事的一点。
2. **音尾的 Pit 往下压，再接一个同样往下走的呼吸音**，吐息感会自己出来 —— 不用手动做气声包络。
3. **`cl` 就是现成的气泡音素材**，配合音区偏移、发声微调，比从别的参数里「蹭」出来干净。
4. **音区偏移的变化平滑、没有突变点**（比张力省心），拿它打底、张力做小补，是 AI 库上最省力的动态方案（用法与六条边界见 **07 §3.2h**）。

## 7. 自定义风格参数（styles）适合谁

`styles[]` 的数据格式与读写工具（`sv_list_voice_styles`、`sv_style_create`、`sv_style_adjust`、`sv_combine_voice_styles`）见 **本文 §5.1/§5.5**。这里只说**什么时候该用**：

- ✅ **适合大批量铺和声 / 合唱层**：整个和声层音色要统一、又不想一个字一个字抠，挂一个风格最省事。
- ⚠️ **主唱轨别靠它表达情绪**：主音轨的起伏要自己画参数。风格向量是「整体染一层色」，做不出「这句要弱、那句要炸」。
- ⚠️ **它是从真人样本里学出来的**：真人音准本来就带偏差，这个毛病也一并被学进去了 —— **用了风格之后可能出现意料之外的跑音**。精细段落务必逐句回听。
- ⚠️ 只有**同 vocoder** 的库之间才能直接搬风格数据（详见**本文 §5.3** 的「风格移植规则」）。

## 8. 调声前的一次性自检清单

- [ ] 库选对了吗？音色底子里有没有我要的那部分？
- [ ] 这是采样库还是 AI 库？该走「换采样」还是「音区偏移」？
- [ ] 要切声线吗？切点落在 `b/p` / `d/t` / `z/c/s` 这类短辅音上了吗？
- [ ] 落差大的声线之间，安排过渡了吗（中间声线的字 / 混比曲线）？
- [ ] AI 自己造出来的动态坑、气泡音，清掉了吗？
- [ ] 低音区 + 快咬字的段落，辅音糊了吗？
- [ ] 用了自定义风格的话，音准有没有跑？

### 5.1 `databases`：声库（nofs JSON）

- 每个声库一个子目录（如 `AiKO PLUS\`、`POPY AI\`），内含 `info.<version>.nofs`
- **flat 版的 nofs 是 JSON**（其他版本为 hex 二进制）；检测：文件以 `{"` 开头
- nofs 顶层字段：`name`（英文名）、`version`、`vendor`、`language`、`phoneset`、`support_languages[]`、`acoustic/vocoder/duration/f0`（模型哈希）、`styles[]`、`f0_style`、`duration_style`
- **`styles[]`**：`[{name, data, extra?}]`，`data` = 256 大写 hex = 128 字节 = **32 个 float32（little-endian）** 风格特征向量（范围约 -0.2~0.2）；`extra` = 8 大写 hex = **1 个 float32**，**可选**（实测 1222 条 style 中 372 条带它）
- `duration_style` / `f0_style` 也是同格式浮点向量（1024 hex）
- **`Refresh` 目录是内置更新器，无实际声库，自动忽略**
- **Electron 里的编辑入口**：设置 → SV 集成 → 「SV Flat 版」——**没检测到 flat 就整块隐藏**；编辑器里「添加 style」**只收 `data`（256 hex，自动转大写）与 `name`（重名拒绝）两个字段**，且只改文本框、点「保存」才落盘（写前自动留 `.nofs.bak`）

### 5.3 风格移植规则

- **只有同 vocoder 的声库风格 data 才兼容**（可直接复制 `{name, data}`）
- 例：POPY AI 与 ROSE AI 同 vocoder（`92e5ef5b`），可互相借 Powerful/Mellow 等
- 改名防混淆：如把 POPY 的 Powerful 复制为 ROSE 的 `popy-powerful`

### 5.4 `translations`：中文名映射

- 位置：`<数据目录>\translations\zh-cn.txt`（**SV2 无此目录，仅 SV1/flat**）
- 格式：`.ini` 风格 `"英文声库名" = "中文名"`，按厂商分组（"Beijing Photek"、"AHS Co., Ltd." 等）
- 示例：`"AiKO PLUS" = "艾可 PLUS"`、`"MEDIUM5·Chiyu PLUS" = "五维介质·赤羽 PLUS"`、`"Kasane Teto" = "重音 Teto AI"`、`"ANRI" = "铃爱莉"`
- **用途**：用户用中文点名声库时，按此表反查英文目录名；列表展示时可附 `zhName` 字段
- 注意：不是所有声库都有中文名（如 POPY AI 无）——无翻译时回退英文名

### 5.5 相关 MCP 工具（`server/src/style-combine.ts`）

| 工具 | 功能 |
|---|---|
| `sv_list_voice_styles` | 按 vocoder 分组列声库 + styles（含 zhName，refresh 忽略） |
| `sv_list_voice_styles_detail` | 单声库 styles 详情（支持中文名） |
| `sv_combine_voice_styles` | 同 vocoder 声库间复制 styles（支持中文名，可改名） |
| `sv_style_create` | 新建 style（baseOnVoiceStyle 复制 / random 随机 + adjust 微调） |
| `sv_style_adjust` | 调整已有 style 的浮点向量（index/count/amplitude） |

- 所有工具**支持中文声库名**（经 translations 反查）；写操作自动备份 `.bak`
- `style.data` 编解码：`dataToFloats`（hex→32 float32 LE）/ `floatsToData`（float32→大写 hex，往返无损）
