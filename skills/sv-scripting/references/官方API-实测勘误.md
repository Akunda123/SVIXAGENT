## `Note.getAttributes()` 与音素级实测（2026-09-18 · SV2 2.2.1）

> ⚠️ **实测补充（2026-09-18 · SV2 2.2.1，先读这条再写代码）**
>
> 1. **`getAttributes()` 只返回"写过的键"**，没写过的属性**根本不在表里**（是 `nil`，不是 `NaN`）—— 文档末句说的是"数值属性取默认值时值为 `NaN`"，**别把两种"没值"混为一谈**。
> 2. **SV2 上这些字段确实存在**（别照抄 SV1 经验就否掉）：**`languageOverride`** / **`phonesetOverride`**（音符级语言 / 音素集覆盖，`""` = 继承）、**`rTone`** / **`rIntonation`**（说唱 tone / intonation）、`dF0VbrMod`、`expValueX/Y`、`phonemes[]`、`muted`、`evenSyllableDuration`。
> 3. 🔴 **`setAttributes()` 不校验字段**：写 SV2 不存在的键（例如那 12 个"Properties only available in version 1"的音高参数）**不报错、静默忽略** ⇒ **凡写属性必须回读验证**，不拿返回值下结论（见 `akdagent-playbook`、`known-bugs.json` 的 `SV-007`）。
> 4. **写语言优先用专门 API**：`setLanguageOverride(lang)`（见下）/ `getLanguageOverride()`；`setAttributes({languageOverride=...})` 是等价候选，**同样必须回读**。
>    语言纪律（默认不改、只在用户反馈多语言混杂时改"少数派"音符）见 **`akdagent-playbook` §0.6b / §0.6c**。
> 5. ✅ **真机已验证（2026-09-18 · SV2 2.2.1 · 用游离 `Note` 对象测，未动工程、未进库）**：
>    - **`setRapAccent("1"…"5")` 可写且可读回**（写 `"3"` 回 `"3"`、写 `"5"` 回 `"5"`）。
>      文档这 5 档"只在普通话里用" —— **它们就是五个声调，`5` = 轻声**（1 阴平 · 2 阳平 · 3 上声 · 4 去声 · **5 轻声**）。
>      ⇒ **按歌词标声调就用它**（配方见 `sv-lyricist/references/说唱词流.md` §5.3）。
>    - **`setAttributes({ rTone = 4, rIntonation = 2 })` 也真写进去了**：`getAttributes().rTone` 回读 `4.0`、`rIntonation` 回读 `2.0`（数值）。
>      ⚠️ 但 **`rTone` 与 `rapAccent` 是两个独立字段**（同时写 accent=`"5"` 与 rTone=`4`，两者各自保留），**`rTone` 在 UI 上对应什么尚未确认** ⇒ 标声调**优先用 `setRapAccent`**。
>    - **`setLanguageOverride("english")` 有效**；**`setAttributes({ languageOverride = "japanese" })` 也有效，且两者是同一个字段**（写完 `getLanguageOverride()` 同步变 `"japanese"`）。
>    - **`setAttributes({ phonesetOverride = "japanese" })` 有效**，回读一致。
>    - `setMusicalType("rap")` 前后 `getMusicalType()` = `"rap"` ✔（游离音符上也成立）。
>    - 写入前 `getAttributes()` 里 **`rTone` / `languageOverride` 等键根本不存在** ⇒ 再次印证第 1 条"只返回写过的键"。
> 6. **rap 周边能力摸底（2026-09-18 · 同一个游离音符）**：
>    - ✅ **可用**：`setPhonemes("hh ah")` / `getPhonemes()` 写读一致（**手动咬字**）；`setAttributes({ evenSyllableDuration=true, muted=true, expValueX=0.25 })` 全部读回（**多音节等分 / 静音 / 表情垫**）；`getRetakes()` 返回 **RetakeList**（`getNumTakes()` = 1，默认 take）。
>    - ⚠️ **游离音符上不生效，需挂在组里再验**：`setPitchAutoMode(false)` **调用即失败**（读回仍 `true`）；`setDetune(0.5)` 调用成功但**读回 `0`**。
>      这两条正好是"说唱三型"（**固定音高 / 随声调 / 语调校**）与"逐音符音分微调"的关键开关 ⇒ **别在没验证前当成能用的能力**。
>    - ❌ **音符级没有**：`setPitchOffset` / `getPitchOffset`（只有 `NoteGroupReference` 级有）。
>    - 📖 **文档有、还没试**：`RetakeList.generateTake(newDuration,newPitch,newTimbre)` / `setActiveTake(id)` / `deleteTake(id)`（**多版本重录、挑 take**，2.1.1+）；`SV#getPhonemesForGroup`（连**默认发音**一起给）；`NoteGroupReference#setVoice({vocalModeParams})` 与 automation 的 **`vocalMode_<Name>`（0-150）**（**段落级声线切换**，取决于声库是否带 vocal modes —— 用户当前工程读出来是**空表**）。
> 7. **音素级属性写入（SV2 · 2026-09-18 真机已验证 · 游离音符）**：
>    - ✅ **`setAttributes({ phonemes = { { position = 0.5, strength = 0.8 }, { leftOffset = 0.05, activity = 0.9 } } })` 真生效**：
>      回读 `#phonemes == 2` 且各项数值逐字一致（`position`/`strength`/`leftOffset`/`activity` 都可写）—— **文档示例的写法就是可用写法**。
>    - 🔴 **`phonemes` 是"整数组替换"语义，不是按项 merge**：只写 `{{ leftOffset = 0.2 }}` ⇒ 数组变成 **1 项**、原来那项的 `position` **变 `nil`（丢了）**。
>      ⇒ **改一项的正确姿势：先把整套 `phonemes` 读回来 → 只改要改的那项 → 把整个数组写回去**（写完回读）。
>    - ⚠️ `setPhonemes("hh ah")` 之后 **`getAttributes().phonemes` 是空数组**（引擎侧还没填）⇒ **别把"空"当成"写失败"**；精准值要等宿主算完（`getComputedAttributesForGroup`）。
>    - ⚠️ **`dur` / `alt` 在 SV2 上没生效**（写 `{ dur = {0.5,1,1} }` 后 `getAttributes().dur` 仍为 `nil`，`alt` 也读不到）——
>      与"这两个字段紧跟 version-1 专属列表"的文档排布一致，**倾向判定为 SV1 专属**；⚠️ 但**只在游离音符上测过，工程内待复验**（见 `sv-project-format` 的「短音符的辅音吃掉前一个音符」节）。
>    - ❌ 另：`setPitchOffset`/`getPitchOffset` 音符级不存在（只有 `NoteGroupReference` 级）；`setDetune`/`setPitchAutoMode` 在**游离音符**上不生效（待挂到组里复验）。
> 8. **临时组实验（SV2 · 2026-09-18 · 自建组 + 引用 + 窗口，测完已删净）**：
>    - ✅ **前置条件三件套是对的**：自建 `NoteGroup`（2 个 `la` 音符）→ `addNoteGroup` → `NoteGroupReference:setTarget/setTimeRange(0,2Q)` → `track:addGroupReference` ⇒
>      `SV:getComputedAttributesForGroup(ref)` **真的回了数据**（每个音符 `l` + `aa` 两个音素）。
>    - ⚠️ **但默认音符的 `position` / `activity` 都是 `nil`**，且 `getAttributes().phonemes` 是**空数组**。
>      ⇒ **推测：这两个字段只在"音素被手动调整过"的音符上才有值**（文档写的是 *"if applicable"*）——
>      这正好解释了为什么仓库里那些 `leftOffset` 数值都来自**手动动过音素的工程**。
>      ⇒ **要定 `position`/`leftOffset` 的口径，必须先在音符上"手动动一下音素"**（写 `setPhonemes` 或写 `attributes.phonemes`）再看 computed。
>    - 🧹 **清理手法（可复用）**：给自建组 `grp:setScriptData("akdagentTemp",1)` 打标记 ⇒ 清理时按标记**倒序** `track:removeGroupReference(i)` + `p:removeNoteGroup(i)` ⇒ 引用数与库数**逐字回到创建前**。
> 9. **两个"读音素"API 的并排实测（2026-09-18 · SV2 2.2.1 · 同一个临时组，测完删净）**：
>
>    | API | 参数 | 实测返回 |
>    |---|---|---|
>    | `SV:getPhonemesForGroup(ref)` | **group reference** | 每个音符**一个字符串**：`"l aa"` ⇒ **只有音素符号**（含 T2P 默认发音），**没有** position / activity |
>    | `SV:getComputedAttributesForGroup(ref)` | **group reference**（⚠️ 不是 `NoteGroup`） | 每个音符一个对象：`phonemes[] = { symbol, language, activity, position }` ⇒ 实测 `l(lang=english, act=nil, pos=nil)` / `aa(lang=english, act=nil, pos=nil)` |
>
>    - 🔴 **字段语义**：`getComputedAttributesForGroup` **能返回"辅音的时长"，返回不了"元音的"** ——
>      这与文档字段名一致（`position` = *"the **consonant** position"*、`activity` = *"the **consonant** activity level"*，**两个字段都只服务辅音**）。
>      ⇒ **SV2 的"精准"只覆盖辅音那一侧**（正好就是我们要修的对象）；**元音时长要自己推**（音符时值 − 辅音时长）。
>      ⚠️ 文档字面是"position（位置）"、用户口述是"时长" ⇒ **两者的具体数值口径还要拿一次真实读数对齐**（待实测）。
>    - ⇒ **带"精准位置/长度"信息的只有 `getComputedAttributesForGroup`**（且**限于辅音**）。
>    - ⚠️ 但**默认音符**上 `position`/`activity` 是 `nil`（`language` 照常回）⇒ 与第 8 条同因（*"if applicable"*）：**先让音素被手动调整过**再看这两个字段。
>    - ⚠️ 两者都是**异步**的：**刚建完组立即调用会返回空数组**（实测 `#==0`），过一会儿再读才有数据（`"l aa"` / 2 个音素）。
> 10. **`activity`/`position` 为什么不出来的实测追查（2026-09-18 · 自建组 · 英文声库 · `la`）**：
>    - 试过：① 纯默认音符 ② `setPhonemes("l aa")` 手动音素 ③ 再写 `setAttributes({phonemes={{strength=0.8}}})` ④ **显式写** `position=0.05 / leftOffset=-0.02 / activity=0.4 / strength=0.9`
>      ⇒ **四种情况 computed 全是 `act=nil, pos=nil`**（④ 的音符属性回读**逐字一致**，证明"写进去了"）。`language` 照常回 `english`。
>    - ⇒ **结论：在这个条件（英文声库 + 英文音素 `l`/`aa`）下拿不到辅音的 `position`/`activity`**，而且**"手动写音符属性"并不会让 computed 报出它们**（计算侧是宿主自己算的，不是回声）。
>    - 🎯 **待复验的主假设**：这两个字段可能**与 rapAccent 一样是"普通话专属"**（文档 *"if applicable"* 的另一种解释）——
>      **要用"普通话声库 + 中文词（如「我」）"再测一次**才能确认。若成立，则"精准辅音时长"在**非普通话**素材上根本不存在（与 SV1 无量化测量其实等价）——这条对 A（辅音抢时间）的方案选择**影响很大**。
> 11. **普通话素材复测 + 异步排除（2026-09-18 · 自建组 · 测完删净）** —— 上面那条主假设**不成立**：
>    - 3 音符组：`我`(默认语种) / `我`(`languageOverride="mandarin"`) / `la`(`mandarin`) ⇒ computed 分别回：
>      `sil`（英文声库不认中文 ⇒ 静音）/ **`w`+`uo`**（mandarin）/ `l`+`a`（mandarin）—— **`activity`/`position` 三者全 `nil`**。
>    - 再测 2 个「我」(`mandarin`)（其中一个 `setPhonemes("w uo")`），**读两次（间隔数秒）仍全 `nil`** ⇒ **不是异步没算完**。
>    - 🆕 **顺带发现（重要）**：`setPhonemes("w uo")` 之后 **`getAttributes().phonemes` 仍然是空数组**（`#==0`）——
>      **T2P 与 `setPhonemes` 都不会填这个数组**；而仓库旧样本文件里的 `leftOffset` 是**在 UI 里手动编辑音素**才出现的
>      ⇒ **推测：`phonemes[]` 这套属性只在"UI 里动过音素时值/边界"的音符上才有内容**，也才可能被 computed 报出来。
>    - ⇒ **A（SV2 侧）的"精准测量"在本机这套环境（SV2 2.2.1 + 当前声库 + 自建组）尚未成立**；**要用户给一个"UI 里手动动过音素"的工程/音符**，或确认是某类声库才支持，才能继续。
>    - ✅ 另：这轮还证明了 **T2P 与声库无关**：英文声库上给音符设 `languageOverride="mandarin"`，`我` 也能转出 `w`+`uo`（只是**渲染**仍要看声库/音素条件）。
> 12. 🔴 **本 API 的性质：`getComputedAttributesForGroup` 与 `getComputedPitchForGroup` 一样，返回的是「渲染值」** ——
>    **不是**"随时可读的属性"，**必须先有渲染产出**（工程真的渲染/播放过、且该组能被渲染）。
>    - 实测对照：自建组（`我`/`你`/`la`，全部 `languageOverride="mandarin"`）**`playback:play()` 播放后**再读 ⇒
>      音素照常有（`w`+`uo` / `n`+`i` / `l`+`a`），但 **`activity`/`position` 依旧全 `nil`**（连 `n`、`l` 这两个辅音也没有）。
>    - ⇒ **判定：我们这套环境（SV2 2.2.1 · 当前声库 · 自建临时组）的渲染没有产出这些值** ——
>      这与 `getComputedPitchForGroup` 在同一环境下**也一直全 null** 是同一个现象（见 §B/§C 与 SV.md 的实测补充）。
>    - ⇒ **要拿 `position`/`activity`，必须在一个"真的能渲染出声音"的工程里读**（用户的真实工程 / 有声库且有音素）。
>      **别再拿"自建组的空值"当结论** —— 那只能说明该组没被渲染。
> 13. 🎯 **拿到了！`activity`/`position` 确实会返回（2026-09-18 · 自建组 · **已渲染**）**：
>    - 判定渲染成功的参照物：**同一状态下 `getComputedPitchForGroup` 回了 8~16 帧数值**（首个 ≈55.5 半音）。
>    - **普通话音素组（「我」「你」「的」，`languageOverride="mandarin"`）**：
>      `我` → `w`/`uo`（nil）· `你` → `n`/`i`（nil）· **`的` → `t`(act=0.98412698412698, pos=0.75539857149124) / `7`(nil)**
>      ⇒ **只有"辅音"（且看起来是塞音这类）才带这两个值**；半元音 `w`、鼻音 `n`、元音/韵母全是 `nil`
>      （这与字段名 *the **consonant** position / the **consonant** activity level* 完全一致，也印证了"给不了元音"）。
>    - **`activity` 是辅音自身属性**：同一歌词「的」在 0.5 / 0.25 / 0.125 s 三种时值下**恒为 0.98412698412698**。
>    - ⚠️ **`position` 的口径仍未定**（三种时值分别 **0.5032 / 0.7165 / 0.7067**；而同一 0.5 s 的「的」在另一组里是 **0.7554**）
>      ⇒ **既不是秒，也不是"占音符时值的比例"**，**与上下文（时值/邻音/所在组）有关**。**要用"变 onset / 变邻音 / 变时值"做一轮对照才能定死。**
>    - 📌 **对 A 的临时结论**：SV2 能拿到**辅音的 `activity`（+ 一个口径未定的 `position`）**，且这两个字段**可写**（`setAttributes`）；
>      虽然口径未定，但**"写 → 重读 `position` 看是否变化"已经能当修正的反馈信号**（不必先知道绝对单位）。
> 14. **`position` 的上下文对照（2026-09-18 · 一个组 6 音符 · 全是 1Q 的「的」· 已渲染）**：
>
>    | # | 歌词 | onsetQ | 前置 | `t` 的 position |
>    |---|---|---|---|---|
>    | 0 | 的 | 0 | 无（组首） | 0.4943 |
>    | 1 | 的 | 2 | 空 2Q | 0.4887 |
>    | 3 | 的 | 4.25 | 啊 0.25Q | 0.7323 |
>    | 5 | 的 | 8 | 啊 2Q | 0.7559 |
>
>    - ✅ **与 onset 的绝对位置无关**（0.4943 vs 0.4887，差 0.006 属噪声级）。
>    - ✅ **与"有没有前置音符"强相关**：**无前置 ≈ 0.49**、**有前置 ≈ 0.71~0.76**（与前置音符的**长短关系不大**：0.25Q 与 2Q 都得 0.73~0.76）。
>    - ⚠️ 仍**不是秒**（0.5 s 的音符不可能有 0.49 s 的辅音），**也不是"占本音符时值的比例"**；
>      最可能是**归一化在"跨音符的某个跨度"上**（把前置音符的时值/边界折进来了），但**具体公式未定**。
>    - ⏳ **下一轮对照（待跑）**：① 固定时值，只把**前置音符改成"以辅音结尾"**（看是否只与前一音素有关）② 固定前置，只改**当前音符时值** ③ 换读音（`的`/`大`/`他`）看 `activity`/`position` 是否只由辅音本身决定。
>    - 🧪 **实验手法（可复用）**：每轮都用**同一个 `scriptData("akdagentTemp",1)` 标记 + 倒序删引用/删组**，并在读之前**先用 `getComputedPitchForGroup` 确认"已经渲染"**（回数值才算渲染成功）。
> 15. **`position` / `activity` 的三组对照（2026-09-18 · 14 音符一组 · 已渲染）**：
>
>    | 音符 | onset/dur (Q) | 前置 | `activity` | `position` |
>    |---|---|---|---|---|
>    | 的 | 0.5 / 1.0 | 啊（元音结尾） | 0.9683 | **0.7819** |
>    | 的 | 2.5 / 1.0 | 安（**`n` 韵尾**） | 0.9524 | **0.7639** |
>    | 的 | 4.5 / 1.0 | 啊 1Q | 0.9841 | **0.7950** |
>    | 的 | 6.5 / **0.5** | 啊 1Q | 0.9683 | **0.7891** |
>    | 的 | 8.0 / **0.25** | 啊 1Q | 0.9683 | **0.7690** |
>    | **大** | 9.25 / 1.0 | 啊 1Q | 0.9841 | **0.8271** |
>    | **他** | 11.25 / 1.0 | 啊 1Q | 0.9841 | **0.5684** |
>
>    - ✅ **与"前置音符的结尾音素"基本无关**（元音结尾 0.7819 vs 鼻音尾 0.7639）。
>    - ✅ **与"当前音符时值"基本无关**（1Q / 0.5Q / 0.25Q ⇒ 0.7950 / 0.7891 / 0.7690）⇒ **它是归一化量，不是时长**（不能当"辅音几秒"用）。
>    - ✅ **与"辅音本身"强相关**：不送气塞音 `t`（的 / 大）≈ **0.76~0.83**，送气音 **`th`（他）≈ 0.568**。

> 24. 🔑 **字段语义（以这条为准）**：

>    - **`activity` / `strength` = 辅音的强度**。
>    - ⇒ **A（辅音抢前一个音符）在 SV2 上的正确改法 = 调 `position`（把辅音出现时间往后推）**，
>      而它**不会动到其他音符/其他部分的时长** —— 这正是我们要的那种"定点、无副作用"的修法。
>    - ⚠️ 与第 23 条的听感实验对照：那次我们只改了 `leftOffset`（−0.1198→0）⇒ 用户听到"**时间没变、只是辅音强度变了**"，
>      与本节语义**自洽**（`leftOffset` 动的是边界/强度那一侧，`position` 才是时间）。

> 25. ✅✅ **定稿：`leftOffset` = 修"辅音抢前一个音符"的开关（2026-09-18 用户听感确认）**：
>
>    **语义（以本节为准）**
>    - **`attributes.phonemes[k].leftOffset`**：**辅音左边界相对其右侧边界的偏移** ——
>      **负值 = 辅音往左延伸**（把前一个音符的时值"抢"过来）；**绝对值 ≈ 提前量**（量级与**秒**吻合：0.1576 配 0.3125 s 的音符）。
>      🔴 **`leftOffset = 0` ⇒ 提前量归零 ⇒ 辅音直接消失**（用户实测："第二个音符辅音没了"）。
>    - `position` = 辅音**出现的时间**（归一化）· `strength` / `activity` = 辅音**强度** · **改这些不会改变其他部分的时长**（纯局部）。
>    - ⚠️ **踩过的坑**：我造的 A/B 对照两组**都把 `leftOffset` 写成 `0.0`** ⇒ **两组的辅音都没了**，对照因此无效（"不知道设置了什么，第二个音符辅音没了"）。**做 A/B 时 `leftOffset` 绝不能设 0。**
>
>    **验证过的修法（真实工程音符 · 用户听感确认）**
>    | 步骤 | 值 |
>    |---|---|
>    | 原始（UI 里的值，听感=**辅音吃掉前一个 `la`**） | `leftOffset = −0.15755441784859` |
>    | 设 `0` | **辅音消失**（❌ 不可用） |
>    | **设 `−0.05`** | ✅ **"这次辅音比例是相对正确的"** |
>
>    **闭环成立**：**读** `getAttributes().phonemes[].leftOffset`（负多少 ≈ 抢了多少）→ **改**（往 0 方向收，实测 `−0.1576 → −0.05` 可用）→ **听感验收**。
>    - 写入姿势：**整数组写回**（`setAttributes({ phonemes = { { leftOffset = …, strength = …, activity = …, position = … }, … } })`）；
>      **空项 `{}` 会被引擎丢掉**、只保留有内容的项；**引擎确实消费写入**（听感会变）——
>      ⚠️ 但**不会反映到 `getComputedAttributesForGroup` 的 `position`/`activity`** ⇒ **写后回读只能验"存进去了"，效果只能听**。
>    - ⚠️ **前提**：该音符最好**已有 `phonemes` 项**（UI 编辑过 / 引擎写过）。没有项时也可以直接写（我们实测能存），但**是否被渲染消费要看它是否有对应音素**。
>
>    **SV1 对照**：SV1 **没有**这套音素级 `leftOffset`，只有 **`attributes.dur`（比例数组，第 0 项=辅音）**，**"只能调比例"** ⇒ 修法是**把辅音项压到 50%~80%**（写小数如 `0.5`）。
> 26. 🔑 **`rTone` / `rIntonation` 的语义（以这条为准）**：
>    - **`rTone` = 说唱"音高趋势"** —— **值高 = 低音到高音（上行）**；**值低 = 高音到低音（下行）**（描述走向，不是绝对音高）。
>    - **`rIntonation` = 音高"整体偏移"**（整个音高的平移）。
>    - 两者**都可写**（`setAttributes({ rTone = …, rIntonation = … })`，真机已验证可写可回读，见第 6 条）；
>      **与 `rapAccent` 是两个独立字段** —— 声调标记走 `rapAccent("1"…"5")`，**别混**。
>    - 📌 用途：用户觉得"rap 声调/语调不准"时，除标 `rapAccent` 外，还可按需给个别音符设**趋势（`rTone`）**与**整体偏移（`rIntonation`）**。

## `SV.getComputedPitchForGroup` 实测（2026-09-18 · SV2 2.2.1）

> ⚠️ **实测补充（2026-09-18 · SV2 2.2.1；含一处自我更正，先读这条再写代码）**
>
> 1. 🔴 **返回的是「长度 = `numFrames` 的数组，无数据的帧为 `null`」——不是空数组。**
>    ⚠️ 用 `#arr` 统计会得到 **0**（Lua 里含 `nil` 的表 `#` 不可靠）⇒ **必须逐帧判 `type(v) == "number"`**，否则会把"一整排 null"误报成"空/0 帧"（我们踩过，整整查了几轮）。
> 2. **要拿到数值，该组必须"真的能被渲染"**，三条缺一不可（缺了就是全 `null`，**且不报任何错**）：
>    · **组要挂在轨道上**（`NoteGroupReference` 存在；**SV2 没有"主组自动存在"**）；
>    · **引用窗口要覆盖内容**（`ref:setTimeRange` 覆盖所有音符）；
>    · **词的语种要跟声库兼容**（例：英文声库 + 中文词 ⇒ **无音素 ⇒ 不可渲染**；语言是**用户的决定** —— ⛔ **默认不改**，见 `akdagent-playbook` SKILL.md **§0.6b**「AKDAgent 整体语言纪律」）。
> 3. **文档原话**：*"does not block and may return an empty array if processing hasn't completed"* ⇒ 判"就绪"要**轮询同一位置、看 `null` 何时变成数值**，不要拿一次结果下结论。
> 4. **`blickStart` 是"绝对位置"**：等于目标 `NoteGroupReference` 的绝对坐标（**已含它自己的 time offset**，见下方原文）。
>    同一个 NoteGroup 被多个 reference 引用时，**不同 reference 算出的音高可能不同**（速度/声线不同）。
>    排查"读回来的值不像我预期的那个音符"时，**先核对 `getTimeOffset()` / `getOnset()`**，再看采样区间。
